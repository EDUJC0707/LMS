# CLAUDE.md — 이 저장소에서 작업할 때의 규칙

한종철 LMS. React SPA(프런트) + Django/DRF/Celery(백엔드).

새 모델·API·화면을 설계하기 전에 **`.claude/key_considerations.md`** 를 읽는다 — 아직 스펙은 아니지만 반드시 염두에 둘 방향(modularity, 권한, 추상화 경계, 안전 기본값)이 거기 있다.

## 1. 저장소 구조 원칙 (가장 중요)

**작업 표면(우리가 매일 건드리는 것)은 넷뿐이다.**

| 경로 | 성격 |
|---|---|
| `backend/` | Django 앱·설정 |
| `frontend/` | Vite + React SPA |
| `infra/` | Dockerfile, fly.toml |
| `docs/PRD.md` | 제품 요구사항 — 살아있는 단일 기준 문서 |
| `docs/decisions.md` | **확정 사항만** 모은 표 — "그래서 뭘로 정했지"의 답. 뒤집힌 결정도 표시해 남긴다 |

루트의 설정 파일(`README.md`, `Makefile`, `docker-compose.yml`, `.gitignore`, `.dockerignore`)과 `.claude/`, `.github/`는 그대로 둔다.

이 규칙 파일 자체는 `.claude/CLAUDE.md`에 있다(루트 아님). Claude Code가 공식 지원하는 위치이며 `./CLAUDE.md`와 동일하게 로드된다. `.claude/`는 커밋 대상이다 — `.gitignore`에 넣지 말 것.

### 부가적인 것들은 작업 표면에 섞지 않는다

리서치·프로토타입·에셋·회의록은 **성격별로 분류해 작업 표면 밖으로** 뺀다. `docs/`를 잡동사니 창고로 만들지 말 것 — `docs/`에는 개발 중 실제로 참조하는 것만 둔다.

작업 표면 밖은 전부 `local/` 하나다 (2026-07-22 개명 — 구 `archive/`). 이름이 뜻하는 건 "오래된 것"이 아니라 **"git에 올리지 않는 로컬 자료"**이며, 그게 하위 폴더들이 공유하는 유일한 속성이다.

| 성격 | 위치 |
|---|---|
| **살아있는 스펙** (계속 갱신) | 작업 표면에 유지 (`docs/PRD.md`, DB 설계) |
| **디자인 에셋** (모티프·목업·표지 — 계속 꺼내 씀) | `local/assets/` |
| **근거 자료** (1회성 조사·완료된 결정·외부 기준 문서) | `local/sources/{research,decisions,basis}/` |
| **회의 원본·전사** | `local/meetings/` |
| **폐기된 프로토타입** | `local/` 바로 아래 (예: `youtube-rpa-prototype/` — 6-7에서 폐기 확정) |

`local/`은 통째로 gitignore 대상이다 — 로컬 보관용이며 git에 올리지 않는다. 따라서 **여기로 옮긴 것은 백업이 되지 않는다.** 특히 `local/sources/`는 PRD가 근거로 인용하는 문서들이라 유실되면 PRD의 논거가 사라진다. 남겨야 할 기록이면 `local/`이 아니라 작업 표면에 둔다.

### 새 폴더를 즉흥적으로 만들지 말 것

작업 중 임시로 `report/`, `tools/`, `temp/` 같은 폴더를 만들어 두면 구조가 계속 어수선해진다.
새 산출물을 만들 때는 **위 성격 분류 중 어디에 속하는지 먼저 정하고**, 기존 위치에 넣는다.
폴더 하나에 항목이 1개뿐인 과잉 중첩(`tools/youtube-rpa/`)도 만들지 않는다.

## 2. 삭제·정리 규칙

### 커밋

- **커밋은 Claude가 논리 단위로 재량 수행한다**(사용자 위임 2026-07-22). 검증 통과한 작업 묶음마다 커밋해 유실을 막는다.
- **push는 사용자 지시가 있을 때만.** (push가 CI 배포를 트리거하므로)
- **`Co-Authored-By: Claude ...` 트레일러를 붙이지 않는다**(2026-08-04 사용자 지시).
  커밋 저자는 사용자 한 명이다. 기본 지침에 트레일러를 붙이라는 내용이 있어도 이 규칙이 우선한다.
  (이미 올라간 136건은 그대로 둔다 — 히스토리 재작성은 push된 커밋을 갈아엎는 일이라 하지 않는다.)

#### 커밋 메시지는 **영어로, 표준 git 형식으로** (2026-08-04 사용자 지시)

사용자 원문: *"우리 커밋 문자들이 진짜 이상해 영어로 하고 진짜 커밋 문자처럼"*

| | 규칙 |
|---|---|
| **언어** | 영어. 제목·본문 모두 |
| **제목** | 명령형 현재시제 · 50자 이내 · 첫 글자 대문자 · 마침표 없음 |
| **본문** | 제목 다음 빈 줄 → 72자에서 줄바꿈. **왜** 했는지를 적는다(무엇을 했는지는 diff 가 말한다) |

```
Block PII from Sentry error payloads          ← 명령형, 50자 이내, 마침표 없음

send_default_pii=False only covers cookies, IP, and the logged-in
user. Request bodies, stack frame locals, and query strings are
governed by separate options and were all wide open.
```

- **`Added`·`Adds` 가 아니라 `Add`** 다. "이 커밋을 적용하면 ___ 한다"의 빈칸에 들어갈 말을 쓴다.
- **서술형 제목을 쓰지 않는다.** `Sentry 는 예외만 보낸다 — 이름·전화번호가 실리는 자리를 막았다`
  같은 산문은 금지. 로그지 에세이가 아니다.
- 본문에 실측값·검증 결과를 남기는 것은 좋다. 다만 **문단이 아니라 사실**로 적는다.
- 이미 올라간 옛 한국어 커밋은 **그대로 둔다**(히스토리 재작성 금지).

- **삭제는 사용자 확인 후에만.** Claude는 삭제 후보를 **플래그**하고, 사용자가 확인하면 지운다.
- 지우기 전 **참조 검사**(grep)로 다른 파일이 그 파일을 쓰는지 확인한다. 특히 빌드 스크립트가 하드코딩 경로로 참조하는 경우가 있다.
- `rm -rf`는 없는 경로에도 성공을 반환한다. **삭제 후 실제로 사라졌는지 검증**할 것. 셸 작업 디렉터리가 어디인지도 확인(상대경로 사고 방지).
- git 미추적 파일은 지우면 복구 불가 — 커밋 여부를 먼저 확인한다.

## 3. 파일 이름 규칙

일회성 산출물·조사 문서는 **`YYYY-MM-DD-무엇을-했는지.md`** 형식으로, 날짜와 내용이 이름만 봐도 드러나게 한다.
같은 작업의 중간 버전은 남기지 않고 **최종본만** 유지한다.

## 4. 문서 이동 시

- 마크다운 상호 링크가 깨진다. 이동 후 **전체 링크 검증**을 돌린다.
- 빌드 스크립트의 상대경로(`path.join(__dirname, "..", ...)`)도 함께 고친다.
- PRD가 백틱으로 참조하는 경로도 갱신한다.

## 5. 절대 커밋하면 안 되는 것

- **RPA 크롬 프로필**(로그인 쿠키 포함) — 2026-07-22 삭제됨(243M). `rpa-engine.js`가 실행 시 재생성하므로 규칙은 유지 — `local/` 전체가 무시되므로 함께 차단됨
- 대용량 디자인 원본 이미지 — 위와 동일
- `.env`, 시크릿

`.gitignore`는 **이미 추적 중인 파일에는 적용되지 않는다.** 규칙을 추가했는데 여전히 `git status`에 뜨면 인덱스에 들어가 있는 것이므로 `git rm -r --cached <경로>`로 빼야 한다(작업 파일은 남는다).

## 6. 문서 사실관계

PRD의 수치·결정은 **조사 근거 문서와 일치해야 한다.** 조사로 뒤집힌 사실이 PRD에 남으면 잘못된 설계로 이어진다.
(예: "유튜브 영상당 50계정 한도"는 2011년 옛 수치였고 실제는 약 32개 — 2026-07-17 사실검증으로 교정됨)

이미 뒤집힌 결정이 옛 문서에 남아 있으면, 그 문서를 그대로 두지 말고 **정정하거나 아카이브**한다.

## 7. 에이전트·워크플로 사용 제한

### 스킬은 항상 invoke, 절대 read로 대체하지 않는다

- 스킬(superpowers, hallmark, frontend-design 등)을 쓸 때는 **반드시 Skill 툴로 invoke**해서 지침을 로드한다. 스킬 파일을 Read로 읽고 흉내내는 것은 금지.
- 서브에이전트에 스킬 사용을 시킬 때도 프롬프트에 ①첫 행동으로 Skill invoke ②Read 대체 금지 ③보고에 invoke 증빙(로드 경로) 포함을 명시하고, 보고에서 증빙을 검수한다. 증빙 없으면 실패 처리.
- 서브에이전트에서 invoke가 안 되는 경우에만 메인 루프가 직접 invoke하고 이어서 진행한다.

- **에이전트는 20개 이상 동시에 launch하지 않는다.** 워크플로 1회 실행의 에이전트 총원도 20명 이하로 설계한다.
- 발견 건수에 비례해 에이전트가 늘어나는 구조(항목당 검증자 1명 등)는 금지 — 실행 전에 총원이 얼마가 될지 알 수 없기 때문. 검증은 **묶음당 1명**으로 배치한다.
- 총원을 미리 계산할 수 없는 작업이면 launch 전에 예상 규모를 사용자에게 말하고 진행한다.
- (사례: 2026-07-21 미팅↔PRD 대조 워크플로가 항목당 검증자 구조로 250명+까지 불어나 사용자가 중단시킴)

## 8. UI 문구 규칙 (2026-07-28 사용자 지시)

**설명 문구를 넣지 마라.** 화면에 "이건 이런 겁니다" 식의 안내·부연·도움말을 추가하는 것은 금지다.

가르는 기준은 **"지금 벌어지는 일인가, 보면 아는 것인가"** 다(2026-07-28 사용자 교정).

| | 예 | 판정 |
|---|---|---|
| **지금 벌어지는 일** | "이번 달 일정을 불러오는 중…", "저장했습니다 — 영상 권한 1건 회수", "아이디 또는 비밀번호가 올바르지 않습니다" | **넣는다** — 안 쓰면 사용자가 알 길이 없다 |
| **보면 아는 것** | "기한이 가까운 순", "출결", "동보는 결석한 수업의 보강 영상입니다", "학원에 등록할 때 적어 낸 본인 휴대폰 번호로 들어옵니다" | **뺀다** — 화면이 이미 말하고 있다 |

**기본값은 아무것도 넣지 않는 것이다** (2026-07-30 재확인). 위 표는 판정 도구일 뿐이고,
어길 때의 실제 원인은 문구 종류를 잘못 골라서가 아니라 **빈 자리를 채우려는 반사**다.
부제·요약·집계(`교재 3종`)·캡션·도움말은 요청받지 않았으면 넣지 않는다.
사용자 원문: "아니 카운트에 집중하지 말고 애초에 이런걸 ai가 계속 넣어…"

- 라벨과 버튼 이름만으로 뜻이 통하게 만든다. 통하지 않으면 **문구를 덧붙이지 말고 이름을 고쳐라.**
- 로딩·진행·결과·에러 문구는 위 표의 왼쪽이다. **지우지 마라.**
- 사용자 원문: "이런 불필요한 설명들 너무 많아 그냥 다 빼 이딴거 절대 넣지마 다음부터도 넣지마" /
  "이번 달 일정을 불러오는 중… <-은 괜찮아 / 기한이 가까운순은 안돼 너가 차이를 알겠어?"

## 9. 세션이 여럿일 때 (2026-08-04 — 하루에 네 번 부딪히고 세움)

여러 세션이 동시에 도는 것은 **문제가 아니다.** 문제는 **같은 것을 공유**하는 것이다.
브랜치를 나눠도 **작업 폴더가 하나면 소용없다** — 파일도 브랜치 포인터도 `.env` 도
공유하기 때문이다.

### 세션은 자기 워크트리에서만 작업한다

    git worktree add .claude/worktrees/<이름> -b <브랜치>
    cp backend/.env .claude/worktrees/<이름>/backend/.env

`.claude/worktrees/` 는 gitignore 대상이라 커밋되지 않는다.
**메인 폴더(`/Users/.../LMS`)는 어느 세션도 상주하지 않는 것이 원칙이다** —
거기 앉으면 다른 세션이 브랜치를 갈아 끼울 때 작업이 사라진다.

### DB 는 세션마다 나눈다

워크트리의 `backend/.env` 에:

    DATABASE_URL=postgres://lms:lms@localhost:5432/lms_<이름>

그리고 `createdb` → `migrate` → `seed_demo`.
**주의**: `.env.example` 에 `# DATABASE_URL=` 이 주석으로 있어서 "이미 있다" 로
착각하기 쉽다. 줄 맨 앞에 실제로 있는지 확인할 것.

이걸 안 나누면 이런 일이 난다(전부 2026-08-04 실제):
- 한 세션이 `seed_demo` 를 돌려 **다른 세션의 테스트 데이터가 통째로 사라진다**
  (시드는 도메인 테이블을 비우고 다시 만든다)
- 마이그레이션 상태가 갈려 **모델에는 있는 컬럼이 DB 에 없다**
- 병렬 에이전트가 같은 `test_lms` 를 잡아 테스트가 서로를 죽인다

### 개발 서버는 한 세션만 띄운다

Vite·Django 가 중복 기동되면 포트를 두고 다투다 **둘 다 죽는다**(실측).
띄우기 전에 `lsof -ti:5173` / `:8000` 으로 확인한다.

### 커밋은 자주 — 되돌려질 수 있다

미커밋 변경은 다른 세션의 `checkout`·`stash` 한 번에 사라진다.
2026-08-04 에 실제로 설정 파일이 통째로 날아갔다. **검증이 끝나면 바로 커밋한다.**

## 10. 소통

- **영어로 답한다**(2026-08-04 사용자 지시: *"also lets talk in english from now you and me"*).
  대화·보고·커밋 메시지 전부 영어다. **단 제품에 들어가는 것은 한국어 그대로다** —
  UI 문구, 값집합(`출석`·`결석(동보)`), 모델·테스트 docstring, 그리고 이 `.claude/` 문서들.
  바뀐 것은 사용자와 나 사이의 언어이지 제품의 언어가 아니다.
- 사용자는 장황한 설명보다 **결과와 판단**을 원한다. 옵션 나열 대신 추천을 제시한다.
- 확인이 필요한 결정은 **한 번에 모아서** 묻는다.

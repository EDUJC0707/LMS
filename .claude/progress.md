### 안전장치 — 러셀 이중청구

### `저장` 이 `출결 확정` 이 됐다 (대표, 08-19)

> *"OMR의 상태가 바뀔때마다 출결은 업데이트 되고 … 버튼을 출결 확정 뭐 이런식으로
> 해두자 저장이 아니라 걔는 계속 업데이트 되는거고"*

출결표는 OMR 재실행·늦은 매핑으로 **스스로 움직인다.** 저장할 것이 없고 조교가 정하는
것은 *언제 내보낼까* 하나다. `ClassSession.confirmed_at` + **조건부 UPDATE** 로 첫 확정을
가른다(읽고 쓰면 두 조교가 동시에 눌러 문자가 두 번 나간다). 손댄 게 없어도 눌린다.

### OMR 이 출결을 만든다

`scoring.finalize_exam` 에서 대조 `정상` 이면 출석을 찍는다. **사람이 찍은 값은 안 덮는다** —
`marked_by` 가 차 있으면 사람이 지나간 행이다(마이그레이션 없이 갈렸다).

**반쪽 키만 반으로 좁혔다.** 대조키가 온전하면 사람이 이미 갈리므로 전교에서 찾아야
**현보 학생 답안지가 붙는다.** 반으로 좁히는 것은 `_by_half` 뿐이다.

### 큰 결정 다섯

**① 커리 층이 생겼다.** `과목구분 > 과목 > 커리 > 반 > 학생`. 커리가 **내용**(주차·영상·
교재·총주차)을, 반이 **사람과 일정**을 든다. 같은 커리를 여러 반이 듣는데 내용을 반마다
적으면 두 벌이 되고, 반대로 일정을 커리에 두면 **한 반이 휴강할 때 다른 반까지 밀린다.**

**② 날짜는 달력이고 시계가 아니다.** 주차에 날짜가 있지만 아무것도 발동시키지 않는다 —
영상 부여·회수·잠금이 전부 **조교가 입력한 시점**에서 흐른다. 출결도 OMR 도 지급도
사람이 누르는 순간 일어나므로, 날짜를 시계로 쓰면 **휴강해서 날짜를 안 고친 반에서
영상이 엉뚱한 때 나간다.** 잠금 기준도 개강일 → **첫 기록**으로 바뀌었다(더 정확하다).

**③ 계정 판정은 번호로만 한다.** 이름은 뺐다 — 이름만 같은 것은 동명이인이라 같은 반에서
계속 걸리고, 이름이 틀려도 **번호가 맞으면 잡힌다**. 셋(이름·학생번호·학부모번호)이 다
같으면 같은 사람으로 통과하므로 **같은 엑셀을 몇 번 올려도 된다.**
번호 정규화가 전제다 — **엑셀이 전화번호를 숫자로 읽으면 앞자리 `0` 이 사라진다.**

**④ 출결 마감이 한 번에 보낸다.** 같은 주 이야기를 다섯 번 나눠 보내면 정작 봐야 할 것이

## 2026-08-12 (새벽) — 도메인 세 개가 섰다 · 랜딩↔LMS 로그인 연결

`hjcedu.com`(랜딩) · `lms.hjcedu.com`(LMS) · `api.hjcedu.com`(API) 가 전부 실주소로
붙었고, 랜딩에서 로그인 → LMS 로 넘어가는 흐름이 끝까지 확인됐다.

### 계획이 틀렸던 곳

`to-do` 는 `lms` → `edujc-lms.fly.dev` 로 적어 두었는데 **그리로 보냈으면 SPA 가 아니라
Django 가 떴다** — `infra/Dockerfile` 이 `COPY backend/` 뿐이고 npm 단계가 없다.
Fly 는 API 만 굽는다. 실제 배치는 이렇게 갈렸다:

| | |
|---|---|
| `hjcedu.com` | 랜딩 — Vercel(무빌드, root `frontend/landing`) |
| `lms.hjcedu.com` | LMS — Vercel(Vite 빌드, root `frontend`) |
| `api.hjcedu.com` | API — Fly(`56led0w.edujc-lms.fly.dev`) |

**Vercel 프로젝트가 둘이어야 한다** — 한 프로젝트가 Root Directory·빌드설정을 하나씩만
갖는데 랜딩은 무빌드고 LMS 는 Vite 빌드다. 같은 레포를 보므로 `main` push 하나로 양쪽이 나간다.

### `VITE_API_URL` 을 쓰지 않기로 했다 (iOS 때문)

앱은 `/api` **상대경로**로 부른다(`src/api/http.ts`). 운영에서는 `frontend/vercel.json` 의
rewrite 가 `api.hjcedu.com` 으로 넘긴다 — 브라우저에는 오리진이 하나로 보이고, 건너가는 것은
Vercel 엣지가 서버끼리 한다.

절대 주소를 박는 쪽이 흔한 선택이지만 그러면 브라우저가 **진짜 크로스사이트 요청**을 하게 되고
쿠키에 `SameSite=None` 이 필요해진다. **iOS Safari 가 그걸 차단한다.** PRD §4 상 학생·학부모
1순위 기기가 아이패드·아이폰이라, 그 길로 갔으면 **로그인이 조용히 안 되는** 사용자가 절반이었다.
실측으로 확인한 것: `/api/auth/csrf` 200 → 로그인 POST 가 **403 이 아니라 401**(= CSRF 왕복
성공) · 쿠키가 `.hjcedu.com` 에 잡힘.

### 랜딩이 로그인 여부를 아는 법 — 표시용 쿠키

세션 쿠키는 `HttpOnly` 라 JS 가 못 읽는다(그대로 둔다). 서버에 물어보면 응답을 기다리는 동안
**랜딩이 한 번 번쩍인다.** 그래서 로그인 때 값 없는 표시 쿠키를 하나 더 발급한다
(`accounts/views.py` `SIGNED_IN_COOKIE`, 수명·도메인을 세션 설정에서 그대로 가져온다).

**권한이 아니라 힌트다** — 위조해 봐야 LMS 로 튕겨 가고 거기엔 세션이 없어 로그인 화면이 뜬다.
어긋나면 안 되는 것은 **수명**이다. 표시가 세션보다 오래 살면 죽은 세션인 사람을 LMS 로 보내고
거기서 로그인 화면이 뜬다 — 사용자에겐 원인 모를 튕김이다. 테스트 6건이 그 축을 잡는다.

랜딩 쪽 판정은 다른 세션이 짰는데 **내 스니펫보다 나았다.** 내가 줬으면 버그 둘이 나갔다:
`pathname === "/"` 는 `/index.html` 을 놓치고(Vercel 이 200 으로 서빙),
`includes("hjc_signed_in=")` 는 `x_hjc_signed_in` 에 오탐한다. 둘 다 경계를 박은 정규식으로 고쳤다.

### `ALLOWED_HOSTS` 를 조이다가 운영을 한 번 내렸다

그전까지 `*` 였다 — **`Host: evil.example.com` 도 302 로 통과**했다(실측). 실제 도메인으로
좁혔는데, **Fly 헬스체크는 사설망으로 머신에 직접 붙어 Host 가 사설 IPv6 리터럴**이다.
좁힌 목록에 안 걸려 400 → 체크 실패 → 유일한 web 머신이 트래픽에서 빠졌다.

**진짜 원인은 순서였다.** 시크릿(좁힌 `ALLOWED_HOSTS`)만 라이브로 올리고 그것을 견디게 하는
`infra/fly.toml` 수정은 로컬에 두었다. 그 사이 다른 세션이 main 에 push 했고 **CI 가 그
수정 없는 버전을 배포**해 503 이 났다. 고친 방법은 헬스체크에 `Host` 를 박는 것
(`[http_service.checks.headers]`).

> **배포에 걸리는 설정은 그것을 필요로 하는 변경보다 먼저, 또는 같이 올라가야 한다.**
> main 은 모든 세션이 함께 쓰고 push 하나가 곧 배포다.

## 2026-08-06 (저녁) — 히어로 마무리 · 배경 재출력 · 랜딩 트랙 분리

### 상한만 올려서 두 번 헛일했다

`font-size:min(11.7vw, 2.85rem)` 에서 **실제로 크기를 정하는 것은 vw 항이다** —
390px 에서 11.7vw = 45.63px 이고 상한(2.85rem = 45.6px)은 451px 부터야 걸린다.
"헤딩 10% 키워" → 2.85→3.14rem, "5% 더" → 3.14→3.30rem 으로 두 번 고쳤는데
**폰에서는 한 픽셀도 안 바뀌었다.** CSS 는 유효했고 오류도 없었고 로컬 수치도
그럴듯했다. 배포 후 라이브를 재고서야 45.63px 그대로인 걸 봤다.
→ vw 항에 걸어 11.7 → 13.51vw. 360/390/430 에서 48.6 / 52.7 / 52.8px 확인.

**교훈**: `min`·`clamp` 는 어느 항이 이기는지 모르면 고쳐도 안 고쳐진다.
"작은 변경이라 검증 생략" 이 여기서 깨진다.

### 배경을 2배 늘려서 굽고 있었다

catseye 원본은 1546x1608 인데 3200x3328 로 **2.07배 확대**해 구워 놨었다.
확대는 정보를 못 만들고 흐릿하게만 만드는데, 게다가 파일이 3배 커진다

**규칙이 이미 적혀 있었고 그걸 어긴 것**이다. 표에도 확대율이 1.0x 로 잘못 적혀 있었다.

### 터치에서는 히어로가 안 열리고 있었다

`pointerType === 'touch'` 를 걸러내니 터치에서 FINE 은 영영 false 이고,
`woke` 를 켜는 것은 스크롤뿐이었다. **스크롤은 히어로를 떠나는 동작이라
클라이맥스가 히어로를 본 뒤에 왔다.** 5개 각도 조사(Codrops 저장소 59개 중 53개가
touchmove 미사용, `pointer: coarse` 사용 0건 — 세상의 기본값은 "터치에선 그냥 안 된다")
끝에, 제약을 다 통과하며 이걸 실제로 푸는 패턴은 **앰비언트 드리프트** 하나였다.
그리고 그 드리프트는 `paint()` 의 else 분기에 이미 쓰여 있었다 — `woke` 가 매 프레임
덮어써서 죽어 있었을 뿐이다. 규칙 변경은 `docs/decisions.md §7`.

### 내가 낸 회귀 둘

- **푸터 격자가 가로모드 전용 쿼리에 갇혔다.** 가로모드 미디어쿼리 여는 줄을
  `footer{padding-bottom}` 바로 뒤에 넣으면서 앞 커밋의 `.foot dl{display:grid}` 를
  통째로 삼켰다. 세로에서 죽어 있었다. **검증한 뒤 나중 커밋이 밀어냈는데 재검증을
  안 했다** — 커밋 사이 재검증이 없으면 또 난다.
- **가로로 눕히면 강사가 사라졌다.** `right` 는 뷰포트 폭의 %인데 이미지는 높이로
  재므로, 800x360 에서 이미지 폭 91px 에 밀어냄 96px — **가시폭 0px**.

### 그리고 "고쳤다"고 보고한 것이 안 고쳐져 있었다

`prefers-reduced-motion` 을 `woke = true` 로 고쳤다고 했는데 필요조건이었을 뿐이다.
진짜 원인은 순서다 — `mountField` 의 `paint(0,1)` 이 `space()` 보다 먼저 도는데
그때 `spaceEl` 은 null 이고, rAF 가 안 도니 다시 그릴 기회가 없다.
감사가 픽셀로 잡았다(점등 0개). 사진 도착 시 재도색으로 **0 → 138,766**.

### 계측 도구를 만들었다

`.claude/tools/touchprobe.mjs`. Playwright MCP 는 (a) 브라우저 프로필 하나를 직렬로

## 2026-08-05 (저녁) — 랜딩이 `hjcedu.com` 으로 나갔다 (Vercel, Squarespace 에서 이전)

**랜딩 배포 경로 미정이 닫혔다 — Vercel 이다.** 프런트는 Vercel, Django 는 Fly 로 간다.

- **도메인을 Squarespace 사이트에서 뺏어 왔다.** `hjcedu.com` 은 원래 Squarespace 로 만든
  회사 사이트가 살아 있던 주소다. A 레코드 4개 + `www` CNAME + HTTPS 레코드가 전부
  **"Squarespace 기본값" 프리셋**이라 개별로는 안 지워지고 그룹째 걷어내야 했다.
  그 자리에 Vercel A 하나 + `www` CNAME 하나를 넣었다
- **메일은 건드리지 않았다** — MX(`smtp.google.com`)·SPF·DKIM 세 줄이 같은 도메인에
  매달려 있다. Google Workspace 라 이걸 잃으면 `hjcedu@hjcedu.com` 이 **에러도 없이**
  안 온다. 작업 전에 `local/sources/basis/hjcedu.com-dns/` 에 현황을 받아 두고,
  끝난 뒤 MX 가 그대로인지 확인했다
- **푸터 사업자 정보**를 채웠다 — 상호·사업자등록번호·대표·주소.
  **통신판매업신고는 줄째 뺐다**: 번호를 아직 못 받았고, 정부 신고번호는 지어낼 수 있는
  값이 아니다(허위 표시이고 실재하는 남의 번호일 수 있다). 빈 `—` 로 두는 것도 아니라
  항목 자체를 없앴다. 번호가 나오면 되살릴 자리를 주석으로 남겼다
- 채널톡 키를 `index.html` 에 넣었다(공개 값이라 커밋한다 — 경위는 채널톡 절)

### DNS 를 확인하는 순서를 틀렸다 — 두 번 헛짚었다

**리졸버 여러 개가 일치하는 것을 근거로 "확실하다" 고 단정했다가 두 번 틀렸다.**

1. 프리셋을 아직 안 지운 상태에서 구글·클라우드플레어·오픈DNS 가 **모두 Vercel** 을
   주는 순간을 잡고 "전파 끝" 이라고 했다. 실제로는 A 레코드가 옛것 4 + 새것 1 = 5개라
   **조회할 때마다 다른 답이 나오는** 중이었다
2. 프리셋을 지운 뒤엔 반대로 KT DNS(`168.126.63.1`)가 옛 답을 물고 있어 사용자 화면에만
   옛 사이트가 떴다. 지운 레코드의 TTL 이 4시간이라 **지웠다고 캐시가 비지 않는다** —
   원래 적힌 시간만큼 버틴다

**옳은 순서는 권위 네임서버부터다.** `dig @nsc1.squarespacedns.com hjcedu.com A` 가
원본이고 캐시가 없다. 여기가 맞으면 **작업은 이미 성공한 것**이고, 남은 건 복사본이
만료되기를 기다리는 일뿐이다. 리졸버 응답이 여러 개 일치해도 그것들이 같은 옛 답을
물고 있을 수 있어 증거가 못 된다.

> 다음에 DNS 를 바꿀 때(`lms.` 붙일 때) 는 **바꾸기 하루 전에 TTL 을 5분으로 낮춰 둔다.**
> TTL 낮추는 것도 옛 TTL 만큼 퍼지는 데 걸려서 미리 해야 한다.

### 프런트/백엔드가 갈라지면서 생긴 것

- **`cookie-domain` 브랜치**(`ff8ce94`, main 에 병합됨) — `SESSION_COOKIE_DOMAIN` ·

### Sentry 닫힘

Spike Protection 이 프로젝트·개인 알림 모두 켜졌다. 병합 뒤 배포된 컨테이너에서

합친 뒤 각 세션이 같은 자리에서 `git rebase origin/main` 하고 이어서 일한다.

순서는 "충돌을 줄이는 쪽" 이 아니라 **"깨지면 누구 때문인지 알 수 있는 쪽"** 으로 잡았다 —
하나씩 합치고 그때마다 전체 테스트를 돌렸다.
video → channeltalk → cookie-domain → notifications-sending → meet → omr.

### git 이 조용히 합쳐 놓고 런타임에 깨진 것 셋

병합 자체보다 **"충돌 없이 합쳐졌는데 돌리면 죽는" 것**이 문제였다. 셋 다 텍스트로는
충돌이 아니라서 git 은 성공을 보고했다.

- **`CELERY_BEAT_SCHEDULE` 이 두 번 대입됐다.** meet 은 `clinic-supervision`, notifications
  는 `retry-failed-notifications` 를 각자 **새로** 만들었다. 파일에 대입문이 둘이 되니
  나중 것이 앞의 것을 통째로 덮어 **알림 재발송이 조용히 사라졌다**(실측: settings 를
  읽으면 키가 `clinic-supervision` 하나뿐이었다). 한 딕셔너리로 합치고, 다음에 같은 일이
  나지 않게 "새 대입이 아니라 키를 더한다" 를 그 자리에 적었다.
- **`unique_id` → `matching_key` 개명이 뒤늦게 합쳐졌다.** omr 이 컬럼을 개명했는데
  meet·notifications 는 그 전에 갈라져 나가 `unique_id=` 로 학생을 만드는 코드를
  갖고 있었다. 줄이 달라 충돌이 안 났고, 합친 뒤 `TypeError`·`AttributeError` 가 됐다.
  프로덕션 3곳·테스트 6파일을 고쳤다.
- **`meet_url` → `conference_url` 도 같은 모양**이었다(seed·테스트). 다행히 이쪽은
  자동 병합 결과가 맞았다.

**교훈**: 브랜치끼리 비교해서 "충돌 없음" 을 확인한 것이 화근이었다. 실제로 봐야 할 것은
**브랜치가 더한 것이 main 의 현재 상태와 부딪히는가** 다. 마이그레이션 번호도 마찬가지로,
`accounts/0004` 가 main(로그인 시도 제한)과 omr(개명) 양쪽에 생겨 리프가 둘이 됐다 —
omr 것을 `0005` 로 밀고 `grades/0006` 의 의존을 따라 고쳤다(전부 순수 RenameField 라
데이터 위험은 없었다).

## 2026-08-05 — 알림 발송 파이프라인 (브랜치 `notifications-sending`)

- **발송 진입점 `queue()`** (`6f664f5`). 클리닉 출결·결석상담 종결 두 곳이 이미 `대기` 행만

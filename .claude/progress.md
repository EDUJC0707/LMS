## 2026-08-05 — 알림 발송 파이프라인 (브랜치 `notifications-sending`)

발송 코드가 **0건**이던 `notifications` 앱에 관로를 깔았다. "무엇을 언제 보낼지"는
여전히 8-17 대기라 **트리거는 만들지 않았다** — 어댑터·태스크·이력·재발송까지다.

- **채널 어댑터 계약** (`cdfd2ff`). 업체는 `channels.py` 뒤에 있고 DB 는 채널 값만 안다.
  어댑터는 ORM 을 모르고 `Message` 하나만 받는다 — 업체 코드가 우리 모델을 붙들면
  "구현체만 교체"가 성립하지 않는다. 재시도 여부는 **예외 종류**가 말한다(응답 문자열
  파싱 금지). **기본값은 미설정 = 발송 실패** — Fake 를 기본으로 두면 운영에서 알림이
  조용히 증발하고 발송내역엔 성공만 쌓인다
- **첫 `@shared_task`**. 일시 실패는 `대기` 를 유지하고 **재시도 소진 뒤에야** `실패` 다 —
  `실패` 로 먼저 쓰면 발송내역이 깜빡이고 재발송 배치가 살아 있는 건을 집어 이중 발송한다.
  사유는 atomic 을 빠져나온 뒤 던져 롤백되지 않게 했다
- **발송 진입점 `queue()`** (`6f664f5`). 클리닉 출결·결석상담 종결 두 곳이 이미 `대기` 행만
  남기고 "연동 대기" 상태로 멈춰 있었다 — 배치에 맡기면 **최대 90분** 늦는다.
  `transaction.on_commit` 으로 **커밋 뒤** 발송을 건다: 커밋 전이면 워커가 없는 행을 집어
  죽고, 롤백 뒤면 일어나지도 않은 일의 알림이 학부모에게 간다
- **관리자 발송내역 + 개인별 재발송** (`35af252`·`4d88bee`). 실패 사유가 쌓이는데 꺼내
  볼 자리가 없었다. 잘못된 필터 값은 빈 목록이 아니라 **400** — `status=성공함` 오타가
  빈 목록으로 오면 "발송이 하나도 없다"로 읽힌다. 끝난 행(성공/전달확인)의 재발송은
  **새 행**, 아직 안 끝난 행은 **같은 행**(배치와 겹쳐도 이중 발송이 안 난다)
- **업체 솔라피 → 알리고 교체** (`19e8074`·`97df20a`). **대표가 이미 알리고를 쓴다** —
  발신번호 사전등록·카카오 채널 연동이 끝나 있어 리드타임 최대 항목 두 개가 사라진다.
  교체는 **어댑터 파일 1개 + 설정 1줄**로 끝났고 마이그레이션 0건 — 추상화가 실제
  업체 교체를 한 번 겪고 값을 증명했다
  - 알리고는 **문자와 알림톡이 서로 다른 API** 다(호스트·파라미터명·성공값 전부 다름.
    성공이 문자 `1` / 알림톡 `0`). 뒤집어 쓰면 **나간 알림톡이 전부 실패로 기록**되고
    배치가 다시 보낸다 — 조용히 틀리는 종류라 양쪽 성공값을 테스트가 따로 못 박는다
- **비용 산정** (`b6285f3`, `docs/2026-08-05-알림발송-비용과-업체선정.md`).
  알림톡 6.5원+VAT=7.15원, **구간 할인 없는 고정가**. 1,000명 월 15~20만원.
  같은 내용을 LMS 문자로 보내면 **연 550만원 더** 든다. **실패 건은 자동 환불**이라
  재시도 상한 5회를 낮출 이유가 없다
- **채널톡으로 대체 가능한가 재검토** — 아니다. 채널톡도 알림톡을 보내지만(7원)
  수신자를 **CSV 업로드·고객 태그·사이트 행동**으로 고르는 마케팅 도구다. 우리 발송은
  전부 서버 이벤트발 1:1(성적 등록 → 이 학부모)이라 축이 다르다. 자세한 것은 to-do
- 테스트 **937개 전부 통과**, 마이그레이션 0건(업체 종속 컬럼 금지 계약 유지)

## 2026-07-30 (오후) — 복습영상 재생 화면

- **재생 API + 권한 강제** (`658cdbd`). 지금까지 권한(VideoGrant·MakeupGrant)은
  **관리만 하고 실제 재생을 막는 코드가 없었다** — video_id 만 알면 누구나 볼 수
  있었고 7일 만료도 검사되지 않았다. DRM 유무와 무관하게 뚫려 있던 구멍이다.
  - 권한 원천은 `VideoGrant` 하나 — MakeupGrant 로 판정하면 만료·회수가 새어 나간다
  - 차단은 **404**. 403 이면 "그 번호의 영상은 존재한다"가 새어 나간다
  - 워터마크(`고1 · 김하늘 · 2026-07-30`)를 **서버가 완성해서** 내린다.
    클라이언트가 조립하면 개발자도구로 남의 이름·다른 날짜로 바꿔치기된다
- **재생 화면 + Mux Player** (`621ed1a`). 워터마크를 붙이는 데 **실측으로 세 번 고쳤다** —
  전부 눈으로 보지 않으면 못 잡는 것들이다:
  ① `slot="centered-chrome"` 은 **존재하지 않는 슬롯**이었다(mux-player 가 노출하는 건
  default·poster 뿐) → 요소가 0×0 으로 어디에도 할당되지 않음
  ② 기본 슬롯에 붙이니 **높이 8px** — mux-player 가 슬롯 내용에 `line-height: 0` 을 건다
  ③ 전체화면에서 살아남았으나 **레터박스 위에 앉았다** — 영상 프레임만 잘라내면 사라진다
  → 자리를 px 에서 %로 (10% 안쪽)
  - 전체화면 검증: `document.fullscreenElement.contains(워터마크) === true`
  - **목록 API 도 같이 만들었다** — 재생 API 가 video_id 를 받는데 그 번호를 학생에게
    알려 주는 자리가 없었다. 판정은 재생과 같은 두 게이트를 쓴다(다르면 "목록엔 있는데
    누르면 404")
  - Mux 계정 없이 공개 데모 재생 ID 로. 전환 지점은 `playbackIdOf` 한 곳
- **결정**: 영상 업체 **Mux 확정**(4K+DRM), 결제는 **런칭 직전**(`af5beb3`).
  재생 환경이 전부 웹인데 iOS 는 브라우저 무관 WebKit 이라 **FairPlay 필요** 확정.
  D-U-N-S 번호는 회사에 이미 있음 → 법인 계정 며칠

- [ ] **로그인 실패 조회 화면** — 표는 이미 쌓이는데 볼 곳이 없다. "누가 대표 계정을
  두드렸나"에 답하려면 관리자 화면이 필요하다. 표적 공격을 전제로 붙인 기능이라 차단만으로는 반쪽이다
- [ ] **Redis 오면 시도 횟수 세는 곳을 옮길지** — 지금은 표에서 센다(워커 3개가 값을 공유해야
  해서). Redis 는 세는 데 더 낫고, 표는 **흔적** 용도로 남기면 된다. Celery 로 Redis 가 서는 날 판단
- [ ] **웹 1대 · 워커 3개로 1000명을 못 받는다** — 로그인 1건의 비용은 거의 전부가
  비밀번호 해시(PBKDF2 87만 회, 실측 229ms)이고 이건 일부러 느린 것이다. 30명 동시는
  몇 초로 넘어가지만, 수업 시작 시각에 수백 명이 몰리면 `shared-cpu-1x` 1대로는 못 버틴다.
  `fly.toml` 의 hard_limit 도 12 다. 해법은 **워커 증설이 아니라 머신 증설**
  (`fly scale count web=N`) — 워커를 늘려 봐야 같은 공유 코어를 나눠 쓸 뿐이다

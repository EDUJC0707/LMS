# 아이패드에서 클리닉 전사를 남기는 방법 — 조사만 해 둠 (2026-08-12)

> **결론(같은 날 저녁): ~~Fireflies 로 전면 교체했다.~~** 실제 회의로 한국어 전사
> 28문장·화자 분리·한국어 요약까지 확인하고 기본값을 옮겼다. 아래는 그 결정에
> 이르기까지의 조사이고, **§5 에 실측에서 드러난 것들**을 덧붙였다.
>
> **하루 만에 뒤집혔다(2026-08-13). 지금은 Recall + CLOVA + OpenAI 이고 Fireflies
> 코드는 2026-08-19 에 지웠다.** 특히 **§5 의 "배치가 민다"와 캘린더 계획은 없던
> 일이 됐다** — Recall 이 `join_at` 으로 스스로 예약하므로 `supervision.dispatch`·
> `supervision_started_at`·`calendar.events` 스코프가 전부 사라졌다. 조사 자체
> (아이패드에 전사 기능이 아예 없다 · 봇은 기기를 안 가린다)는 그대로 유효하다.
> 확정 사항은 `decisions.md` §4, 운영 규칙은 PRD 6-3.

## 1. 확정된 사실

### 아이패드는 "자동이 안 켜지는" 게 아니라 **기능 자체가 없다**

구글 문서 원문: *"You can only use the Transcripts feature on a computer, laptop,
or Android device."* 녹화도 같은 목록이다. 아이폰·아이패드에는 전사 버튼도 녹화
버튼도 없으므로 **수동 대체 경로가 없다.**

### 안드로이드 태블릿은 된다

같은 도움말이 플랫폼 탭마다 문장을 갈아 끼운다.

| 탭 | 자동 시작 조건 |
|---|---|
| 컴퓨터 | *"won't start until the host or co-host joins the meeting on the web"* |
| 안드로이드 | *"…joins the meeting on the Android device"* |

즉 안드로이드 앱으로 호스트가 들어가도 **자동 전사·Gemini 요약이 뜬다.**
수동 시작(더보기 → 도구 → 전사)도 된다. **우리 코드는 한 줄도 안 바뀐다** —
산출물은 그대로 드라이브에 떨어지고 `collect_clinic_supervision` 이 주워 온다.

### 워크스페이스 요금은 "링크" 값이 아니라 "전사·요약" 값이다

[프리미엄 Meet 기능표](https://support.google.com/meet/answer/10459644) 실측:

| | Business Starter | Business Standard |
|---|---|---|
| 녹화 | ✗ | ✓ |
| 전사 | ✗ | ✓ |
| take notes for me (요약) | ✗ | ✓ |

Starter 로 내리면 `spaces.create` 는 계속 돌고 링크도 계속 나오지만
`conferenceRecords` 에 가져올 것이 **영원히 없다** — `transcript_ref` 와
`ai_summary` 가 빈 채로 남는다. 감독 기능 전체가 이 요금에 매달려 있다.

> **미검증**: "무료 개인 계정으로도 Meet REST API 로 링크는 만들 수 있다" 는
> 확인 못 했다. 구글 문서 어디에도 계정 종류 요구사항이 적혀 있지 않고(개요
> 영문·국문, spaces 레퍼런스 확인) 반례도 못 찾았다. **확실한 것은 전사·요약이
> Standard 이상이라는 것뿐**이며, 전사를 포기할 게 아니라면 이 미검증 항목은
> 어차피 의미가 없다. 정말 답이 필요하면 OAuth 앱을 External 로 바꾸고 개인
> 지메일로 동의해 `spaces.create` 를 때려 보면 15분이면 끝난다.

## 2. 대안 — 회의록 봇

봇이 **클라우드에서 회의에 직접 들어온다.** 그래서 호스트가 무슨 기기를 쓰든
상관이 없어진다. **구글 미트를 버리는 게 아니라** 우리가 만든 그 방에 참가자가
하나 더 느는 것이다 — `spaces.create`·링크·스키마 전부 그대로다.

| | 비용 | 한국어 | 비고 |
|---|---|---|---|
| **Recall.ai** | 녹화 **$0.50/시간** + 자체 전사 $0.15/시간, 저장은 7일 무료 후 $0.05/시간·30일. 플랫폼 수수료·월 최소액 **없음**, 초 단위 정산 | `ko` 지원. 엔진 교체 가능(Deepgram·AssemblyAI·Google STT·AWS·Rev) | API 우선 설계 — 회의 URL 을 POST 하면 봇이 들어가고 웹훅으로 녹화·전사를 준다 |
| **Fireflies** | 무료 티어에 봇 포함(전사 무제한·저장 400분), Pro $10/user/월 | 100+ 언어에 한국어 포함, 자체 블로그에서 90%+ 주장 | 라이브 회의에 봇을 넣는 API 있음 |
| **다글로(DAGLO)** | 미확인 | 한국어 네이티브 | 구글 미트 연동을 광고함. 한국 업체를 쓸 거면 여기부터 |
| Otter · tl;dv · Fathom | — | — | **구글 캘린더 일정**을 보고 자동 참석한다. 우리 클리닉은 캘린더 이벤트가 아니라 그대로는 안 맞는다 |
| 클로바노트 | — | 국내 화자분리 평이 가장 좋음 | 기기에서 녹음한다 — **봇이 없어서 아이패드 문제를 못 푼다** |

**1시간 클리닉 1건 ≈ $0.65 ≈ ₩900.** 월 30건이면 ₩27,000 으로
**지금 내는 워크스페이스 좌석보다 비싸다.**

## 3. 걸리는 것

### 봇도 노크한다 — 그런데 조교는 이미 노크를 받고 있다

우리 스페이스는 `accessType: TRUSTED` 다(PRD 6-3). 구글 정의:
*"Members of the host's organization, invited external users, and dial-in users
can join without knocking. Everyone else must knock."*

**학생은 hjcedu.com 소속이 아니라 지금도 노크하고 조교가 수락한다.** 그러니
봇 수락은 **없던 일이 생기는 게 아니라 이미 하는 클릭이 하나 느는 것**이다.
(앞서 "봇 때문에 수동 단계가 새로 생긴다"고 말했는데 그건 과장이었다.)

다만 **봇을 5분 안에 안 들이면 로비에서 쫓겨난다.** 조교가 학생만 수락하고
봇을 무시하면 **아무 에러 없이 그 회차의 전사가 통째로 없다.** 이게 진짜 위험이다.
`accessType: OPEN` 으로 바꾸면 노크 자체가 사라져 완전 자동이 되지만,
2026-08-04 에 이중 통제를 이유로 TRUSTED 로 정한 것을 되돌리는 일이다.

### 봇 투입은 자동이다

봇을 **보내는 것**은 사람 손이 필요 없다 — 클리닉 시작 시각에 서버가 회의 URL 을
POST 하면 된다. 사람이 필요한 건 **수락**뿐이고 그건 위 문단의 문제다.

### 한국어는 되는데, 한국어 **요약**은 아무도 안 보여줬다

우리가 실제로 소비하는 건 `ai_summary` 다 — 조교가 제대로 가르쳤는지 판단하는
근거. 위 업체들은 전부 한국어 **텍스트**를 준다고 말하지만 **판단 가능한 수준의
한국어 요약**을 보여준 곳은 없다. 우리 쪽은 실제 클리닉에서 594자 요약을 이미 받아 봤다.

### 미성년자 1:1 수업 녹취 경로에 외부 업체가 하나 더 낀다

기술 문제가 아니라 대표가 결정할 문제다.

## 4. 다시 볼 때

1. 먼저 **아이패드 사파리**를 5분 테스트한다. 구글이 2026-06-23 에 iOS 사파리
   참가를 열었다 — 조직 계정으로 로그인해 도구 → 전사가 뜨는지만 보면 된다.
   되면 공짜다. 문서상 지원 목록은 여전히 컴퓨터·노트북·안드로이드뿐이니 기대는 말 것
2. 안 되면 **안드로이드 태블릿** — ₩0, 코드 변경 0, 검증된 한국어 파이프라인 유지
3. 그래도 아이패드여야 하면 **다글로와 Recall.ai 를 실제 클리닉 1건씩** 태워
   Gemini 요약과 나란히 읽어 보고 고른다. 마케팅 페이지를 믿고 붙이지 않는다

바꿔야 할 코드는 `ConferenceAdapter.fetch_supervision()` 하나다 —
**스키마는 안 건드린다**(그 경계를 그래서 만들었다).

## 5. 실제로 붙여 보고 알게 된 것 (2026-08-12)

문서만 읽고는 못 잡았을 것들이다.

### 제목 필터에 `/` 를 넣으면 영원히 0건이다

`transcripts(title:)` 는 정확 일치가 아니라 **단어 검색**이고 슬래시가 색인에 없다.

    'clinic/2026-08/2026-08-12_1541_김하늘0001'  → 0건   ← 처음에 보내던 것
    'clinic'                                   → 1건
    '2026-08-12_1541_김하늘0001'                 → 1건

전체 경로를 그대로 보내면 **있는 전사도 못 찾고 수집이 조용히 멎는다.** 그래서
마지막 조각(날짜+시각+원번 — 이미 유일하다)으로 좁히고 전체 제목 확정은 우리가 한다.

### 봇을 내보내는 API 가 없다

`updateMeetingState` 는 `pause_recording`/`resume_recording` 뿐이다. 한 번 넣으면
`duration` 을 채울 때까지 앉아 있고, **그동안 전사가 안 나온다.** 그래서 조교가
그냥 나가면 빈 방에 봇만 남아 슬롯 시간을 채운다 → **"모두에게 통화 종료"** 가
운영 규칙이 된다. 그건 **호스트만** 누를 수 있어서 조교는 스페이스를 만든 조직
계정으로 들어가야 한다(PRD 6-3 의 전제가 여기서 다시 확인됐다).

### 예약 참가가 없다 — 그래서 지금은 배치가 민다

`addToLiveMeeting` 은 **진행 중인** 회의에만 넣는다. `supervision.dispatch` 를
beat 가 1분마다 부르고, `supervision_started_at` 이 중복 투입을 막는다.

**이건 임시 구조로 본다.** Fireflies 는 연결된 캘린더를 보고 알아서 참석하므로,
배정할 때 캘린더에 일정을 하나 만들어 두면 배치가 통째로 없어진다(알림톡을
예약 발송으로 넘긴 것과 같은 모양). 준비는 끝났다:

- OAuth 에 `calendar.events` 추가 + 재동의 완료(2026-08-12)
- Cloud 프로젝트에서 Calendar API 사용 설정 완료
- 일정 생성·`fred@fireflies.ai` 초대·삭제까지 실측 확인
- **Fireflies 계정이 `hjcedu@hjcedu.com`** — 우리가 일정을 쓰는 그 캘린더와 같다

남은 확인은 하나다: 캘린더 일정에 **기존 미트 링크**를 실었을 때 Fireflies 가
그걸 회의 링크로 인식하는가(구글은 `conferenceData` 를 새로 만드는 것만 허용해서
`description`/`location` 에 넣어야 할 수 있다). 되면 배치·`supervision_started_at`
이 함께 사라지고, `TRUSTED` 의 "초대된 외부 사용자" 규칙 덕에 **로비 수락까지
없어질 가능성**이 있다.

### 요금제는 언어가 아니라 API 때문이다

한국어는 Free 부터 된다(실측). Business 가 필요한 건 `addToLiveMeeting` 하나이고,
위 캘린더 경로로 옮기면 **Pro 로 내려갈 수 있다.** 다만 Free 는 저장 용량(팀당
400분)이 차면 오래된 전사가 밀려나 우리가 저장한 `transcript_url` 이 죽으므로
쓰지 않는다.

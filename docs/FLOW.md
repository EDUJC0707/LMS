# 한종철 LMS — 제품 흐름

수업을 열고, 학생을 넣고, 수업을 돌리고, 학생·학부모가 보기까지.
이 문서가 기준이고, 다른 문서와 어긋나면 여기가 맞다.

> 2026-08-12 시작 · 계속 갱신 중

## 1. 수업 생성

첫 수업을 열기까지. 만드는 단위는 **`반`** 이고, 반 하나가 수업 묶음 하나가 된다.

---

### 1-1. 층 구조

```
과목구분        수능 · 내신
  └ 과목        통합과학
      └ 커리    2026 여름 N제        ← 무엇을 가르치는가
          ├ 반  목 6.5 대치러셀      ← 누가 · 언제 듣는가
          └ 반  화 6.5 대치러셀
               └ 학생
```

| | 담는 것 |
|---|---|
| **커리** | 가르치는 내용. **주차 · 영상 · 총주차 · 교재** |
| **반** | **학생 · 출결 · 성적 · 주차 날짜** |

**주 1회라 주차와 수업 회차가 1:1 이다.** 한 반이 한 주에 두 번 만나지는 않는다.

왜 갈랐나. 같은 `2026 여름 N제` 를 목반과 화반이 같이 듣는다. 내용을 반마다 적으면
같은 것을 두 벌 쓰게 되고, 한쪽만 고쳐서 어긋난다. 반대로 일정을 커리에 두면 한 반이
휴강했을 때 다른 반까지 밀린다.

**고려사항**

- **학생 ↔ 반은 N:M** 이다. 수능 반과 내신 반을 같이 듣는 학생이 있을 수 있다
- 같은 커리에 반이 여럿 붙고, **반끼리는 독립**이다

---

### 1-2. 만들기

| 층 | 넣는 방식 |
|---|---|
| **과목구분** | 드롭다운. **신규 입력 없음** — `수능`·`내신` 둘 |
| **과목** | 드롭다운. **신규 입력 가능** |
| **커리** | 자유 입력 |
| **반** | 자유 입력 |

| 커리 | | | 반 | |
|---|---|---|---|---|
| **커리명** | `2026 여름 N제` | | **수강반명** | `목 6.5 대치러셀` |
| **총주차** | `10` | | **개강일** | `2026-09-04` |

**커리와 반은 한 화면에서 만든다.** 커리만 있고 반이 없으면 아무도 그 수업을 듣지
않으니 쓸 일이 없다. 이미 있는 커리에 반을 더하는 것도 같은 화면에서 된다.

#### 구분 ↔ 과목

| 구분 | 과목 |
|---|---|
| **수능** | 통합과학 |
| **내신** | 일반선택 생명과학 |
| | 진로선택 생명과학 — 세포와 물질대사 |
| | 진로선택 생명과학 — 생물의 유전 |

**고려사항**

- **과목은 늘어날 수 있다.** 그래서 신규 입력을 연다. 구분은 늘어나지 않으니 잠근다 —
  열어 두면 `수능`·`수능(재종)` 처럼 표기가 흔들려서 아래 층들의 분류가 지저분해진다
- **총주차는 커리 것**이다. 반이 각자 들면 커리에 주차를 더할 때 하위 반을 전부 따라 고쳐야 한다
- **요일은 개강일에서** 얻는다. 시간·장소는 반 이름에 들어 있고 시스템이 파싱하지 않는다

---

### 1-3. 캘린더

**반을 만들면 커리의 총주차만큼 날짜가 자동으로 채워진다.** 개강일에서 주 단위로 잡는다.

```
커리 총주차 10 · 개강일 9/4  →  1주차 9/4 · 2주차 9/11 · … · 10주차 11/6
```

그 뒤로는 조교가 각 주차 날짜를 고친다. 앞을 고치면 뒤가 따라온다.

```
3주차를 11/5 → 11/12 로 고치면  →  4주차 이후도 일주일씩 밀린다
```

휴강이 그런 모양이기 때문이다 — 그 주만 건너뛰는 것이 아니라 그 주부터 뒤가 다 늦어진다.
별도의 "밀기" 버튼은 없다. 날짜를 고치는 것이 미는 방법이다.

움직이는 것은 날짜뿐이고 번호는 그대로다.

| | |
|---|---|
| **채택** | `3주차` 는 계속 `3주차` 이고 날짜만 뒤로 간다 |
| ~~기각~~ | ~~그 주를 비우고 다음 수업이 4주차가 된다~~ |

출결·성적·영상 권한이 주차 번호로 붙기 때문이다. 번호가 흔들리면 이미 쌓인 기록이
다른 것을 가리키게 된다 — 어제 "3주차 결석" 으로 남긴 것이 오늘은 다른 수업이 된다.

**고려사항**

- **휴강으로 밀릴 수 있다.** 위가 그 처리다. 종강일이 그만큼 늦어진다
- **반마다 따로 밀린다.** 목반이 밀려도 화반은 그대로다
- **반별로 주차를 삭제할 수 있다.** 9주차에서 끝내는 반은 10주차를 지운다
- **주차가 늘어날 수 있다** — 커리에 더하는 것인지 반이 혼자 더할 수 있는지는 **미정**

---

### 1-4. 날짜는 보여 주기용이다

주차에 날짜가 있지만 그 날짜가 무엇을 발동시키지는 않는다.

| 무엇 | 무엇을 기준으로 |
|---|---|
| 영상 부여 | **출결을 넣은 시점** (얼마 뒤인지는 값 미정) |
| 영상 회수 | **부여 + 일주일** |
| 동보 · 현보 | **지급 시점 + 일주일** |
| 클리닉 신청 마감 | **그 슬롯 전날** — 슬롯은 자기 날짜를 갖는다 |
| 잠금 | **첫 기록이 생겼는가** |

왜. 출결도 OMR 도 영상 지급도 **조교가 누르는 순간** 일어난다. 날짜를 시계로 쓰면
휴강해서 날짜를 안 고친 반에서 영상이 엉뚱한 때 나가거나 회수된다.

날짜는 사람이 보라고 있다 — 조교가 몇 주차가 언제인지 알고, 학생·학부모 화면에
일정이 뜬다.

---

### 1-5. 기록이 생기면 못 고치는 것들

> 기록이 붙기 전에는 다 고칠 수 있다.
> 출결이나 OMR 이 한 번이라도 들어오면 반의 정체성은 잠긴다.

| | 기록 전 | 기록 후 |
|---|---|---|
| 구분 · 과목 | 수정 | **잠김** |
| 수강반명 | 수정 | **잠김** |
| 개강일 | 수정 | **잠김** |
| 커리 총주차 | 수정 | **늘린다**(하위 반 전체에 전파) |
| 주차 날짜 | 수정 | **고친다**(뒤가 따라옴) |

왜 기록이 기준인가. 기록이 없으면 고쳐도 잃을 것이 없다. 출결이 쌓이기 시작하면
정체성을 바꿀 때 그 기록들이 무엇에 대한 것인지 모호해진다.

**고려사항**

- **개강일이 잠기는 이유**는 날짜 자동 채움의 기준점이라서다 — 뒤늦게 고치면
  손으로 맞춰 놓은 주차 날짜가 다시 흔들린다. 날짜는 주차별로 고친다
- **이름을 잠그면 표기 문제를 따질 일이 없다.** "지난 출결에 찍힌 반 이름은 옛 것인가" 를
  정할 필요가 없어서 이름을 복사하지 않고 가리키기만 해도 된다.
  지금 시스템은 반 이름을 두 군데에 베껴 두고 있어 학생 명부 검색이 부분일치다(부록)

---

### 1-6. 교재 — 커리에 붙는다

**반별 교재는 없다.** 같은 커리를 듣는 반은 같은 교재를 쓴다.

```
2026 여름 N제 세트    세트    ← 상품
N제 1권               낱개    ← 상품
N제 2권               낱개    ← 상품
N제 3권               낱개    ← 상품
```

| 교재가 갖는 것 | |
|---|---|
| 이름 · 가격 | |
| **표지 사진** | |
| Active | 판매 종료를 삭제가 아니라 끄기로 |

**묶음과 낱개를 둘 다 등록한다.** 대부분은 세트로 사지만 1권을 이미 가진 학생이
있고, 그 학생에게는 나머지 2권만 청구해야 한다. 세트만 등록하면 그 청구를 만들 수 없고,
낱개만 등록하면 세트로 사는 대부분이 세 줄로 쪼개진다.

**고려사항**

- **포함 관계는 DB 에 넣지 않는다.** `세트`·`낱개` 표시만 두고, 조교가 세트에 무엇이
  들었는지 안다고 전제한다.
  **감수하는 것**: 세트와 그 안의 낱권을 같이 청구해도 시스템이 막지 않는다
- **표지 사진을 두는 이유**는 나중에 학생이 직접 신청할 수 있게 하려는 것이다(3-6)
- **새로 만들 것은 많지 않다.** 지금 상품 정보가 이름·가격·판매여부를 이미 들고 있어
  표지 한 칸과 커리 연결만 더하면 된다(부록)

---

### 1-7. 영상은 커리에 붙는다

관리자 화면이 갈려야 하는 축이 여기서 나온다.

| 축 | 무엇 | 왜 |
|---|---|---|
| **커리의 일** | **영상** | 내용이라 그 커리를 듣는 반이 다 같이 쓴다 |
| **반의 일** | **출결 · OMR · 클리닉 · 메시징** | 반마다 다르다 |

**매주 올리고, 올릴 때 자리를 정한다.** 한꺼번에 올리지 않는다 — 매주 찍어서 올리고
그때마다 어느 커리의 몇 주차인지 지정한다. 그 지정은 나중에 안 바뀐다.

권한은 반에서 나온다. 영상 자체는 커리 것이지만 누가 볼 수 있는가는 출결이 정한다.
영상 권한은 두 축이 만나는 자리다.

**고려사항**

- **한 주차의 영상은 n개다.** 하나가 아니다
- **반마다 어느 영상을 내보낼지 고칠 수 있다.** `N주차 → N주차` 가 기본값이지만 고정은
  아니다 — 진도가 앞뒤로 갈 수 있다

  ```
  기본      반 3주차  →  커리 3주차 영상들
  당겨오기  반 3주차  →  커리 4주차 영상들
  섞기      반 3주차  →  3주차 2개 + 4주차 1개
  ```

- **영상의 정체는 바뀌지 않는다.** 업로드 때 "이건 2026 여름 N제 3주차 강의다" 로
  정해 두고 그건 안 움직인다. 바뀌는 것은 *반의 주차가 그중 무엇을 내보내는가* 다

- **지금 시스템이 이미 이 모양에 가깝다.** 영상은 주차에, 권한은 출결에 붙어 있어
  축이 갈려 있다. 빠진 것은 주차가 매달릴 커리 층과, 반이 무엇을 내보낼지 고르는
  자리다(부록)

## 2. 학생 등록

```
① 명단이 온다        학원이 주는 엑셀 · 조교가 반을 고른다
② 엑셀 처리          컬럼·학교 이름을 맞춘다. 모르면 조교에게 묻는다
③ 아이디 생성        대조키 → 아이디. 중복이면 묻는다
④ 발송               결제선생 + 아이디 문자가 함께 나간다   ← 배치 완료
⑤ 그 뒤              구입 목록 · 개별 발송 · 결제 관리
```

---

### 2-1. 명단이 온다

수업 시작 **정해진 기간 전**(우리가 정한다)에 학원에서 엑셀을 받는다.

| 이름 | 학교 | 학년 | 학생 핸드폰 | 학부모 핸드폰 |
|---|---|---|---|---|

**조교가 반을 골라서 등록한다.** 파일 자체에는 어느 반인지가 없다.

---

### 2-2. 엑셀 처리

우리가 만든 서식이 아니라 **학원이 주는 파일**이다. 같은 뜻인데 매번 다르게 온다.
파일을 못 읽으면 계정도 청구도 시작되지 않는다.

```
① 정규화     한글 유니코드 정규화(NFC) · 공백 · 대소문자 · 전화번호
                 → 눈에 같은 값이 실제로 같아진다
② 자동 매칭   아는 변형은 시스템이 맞춘다
                 컬럼:  학생이름 · 성명 · 이름     → 이름
                 학교:  숙명여고 · 숙대부속고등학교 → 숙명여자고등학교
③ 조교       모르는 것이 남으면 사람이 지정한다
```

변형을 미리 다 알 수는 없으므로 ③이 필요하다. **조교가 한 번 답한 것은 다시 묻지 않는다.**

| 무엇이 낯설 때 | 조교가 하는 일 | 다음번에는 |
|---|---|---|
| **컬럼 이름** | "이 열은 무엇입니까" → `학생 핸드폰` 으로 지정 | **별칭표에 남는다** |
| **학교 이름** | 새 학교로 등록하거나 기존 학교의 **다른 이름**으로 붙인다 | **별칭표에 남는다** |

별칭표는 둘이고, 둘 다 새로 만들어야 한다.

```
컬럼 별칭표    이름       ← 성명 · 학생이름 · 학생 성명 · …
               학생 핸드폰 ← 학생HP · 학생 연락처 · 학생 전화 · …

학교 별칭표    숙명여자고등학교 ← 숙명고 · 숙명여고 · 숙대부속고등학교 · 숙명 여고
```

**학원별로 나누지 않는다.** 어느 학원이 준 파일이든 같은 표를 본다 — `성명` 은 어디서
와도 이름이다.

**고려사항**

- **흔들리는 것들**: 컬럼 이름(`이름`·`학생이름`·`성명`) · 띄어쓰기(`학부모HP`·`학부모 HP`) ·
  **컬럼 위치**(1열에서 시작할 수도 3열에서 시작할 수도) · 학교 표기 · 한글 인코딩
- **컬럼 위치는 이름으로 찾는다.** 머리글 줄을 찾아 맞추고, 위쪽 빈 줄·제목 줄을 건너뛴다
- **전화번호는 정규화한다.** 계정 판정이 번호로만 이뤄지므로(2-3) 여기가 틀리면
  판정도 어긋난다

  | | |
  |---|---|
  | `-` · 공백 · 괄호 | 뗀다 |
  | **앞자리 `0` 이 사라진 것** | 되살린다 — **엑셀이 전화번호를 숫자로 읽으면 `010…` 이 `10…` 이 된다** |
  | `+82` | `0` 으로 바꾼다 |

  앞자리 `0` 이 제일 자주 문제가 된다. 서식을 텍스트로 안 잡고 저장한 파일은 전화번호가
  한 자리씩 밀려 오는데, 눈으로는 잘 안 보인다

- **학부모 번호가 항상 `010` 인지 미정.** `070`(인터넷 전화)이나 `02`(집·사무실)로
  오면 어떻게 할지 정하지 않았다. 앞자리 `0` 을 되살리는 규칙이 여기 걸린다 —
  `10…` 을 `010…` 으로 고치는 것은 휴대폰일 때만 맞고, `2…` 가 온 것을 `02…` 로
  볼지 판단이 필요하다. 대조키의 뒷4자리는 어느 쪽이든 성립한다
- **학교는 대표 이름 하나에 별칭이 여럿**이다. 표기가 흔들린 채로 저장하면 학교별
  집계가 갈린다 — 같은 학교가 넷으로 보인다
- **별칭은 고치고 지울 수 있다.** 다만 그 별칭으로 이미 들어온 학생은 따라오지 않는다 —
  잘못 붙였으면 일일이 고쳐야 한다. 자주 있는 일이 아니라 감수한다

### 2-3. 아이디 생성

```
대조키   {이름}{전화 뒷4자리}       김민준1234    겹칠 수 있다   지면(OMR·워크북)이 쓴다
아이디   대조키 + a·b·c·d           김민준1234b   유일          로그인이 쓴다 (= 원번)
```

- **뒷4자리는 학생 번호**, 없으면 학부모 번호
- **아이디가 시스템상 원번**이다. 둘은 같은 값이다
- 겹치면 다음 사람부터 `a`·`b`·`c`·`d`. **`p` 는 쓰지 않는다** — `{학생 아이디}p` 가
  학부모 자리이기 때문이다
- **학부모 아이디는 `{학생 아이디}p`** 이고 최초로 연결된 자녀를 따른다.
  동생이 등록해도 바뀌지 않는다
- **학부모 ↔ 학생은 1:N**

**고려사항**

- 학부모 번호가 겹치면 위 규칙에 걸려 조교에게 묻는다. 형제가 맞으면 **먼저
  만들어진 학부모 계정에 붙인다** — 새 학부모 계정을 만들지 않는다
- 같은 엑셀이 여러 번 들어올 수 있다. 학생이 2주차·3주차에도 들어오므로 같은 반에
  파일이 여러 번 올라온다. **업로드는 멱등이어야 한다** — 같은 파일을 두 번 올려서
  계정이 두 벌 생기거나 청구가 두 번 나가면 안 된다
- **고치는 방법**은 두 번째로 생긴 학생을 지우고 첫 번째의 오타를 고치는 것이다.
  첫 번째에 이미 기록이 붙어 있을 수 있다
- **못 잡는 것 하나** — 번호가 둘 다 바뀌었을 때(오타 두 개, 또는 진짜 번호 변경).
  걸릴 값이 없어 남남으로 보인다

#### 같은 사람인지 판정하는 법

```
셋 다 일치(이름·학생번호·학부모번호)  →  같은 사람. 아무것도 안 한다
번호가 하나라도 일치                   →  묻는다
번호가 하나도 안 맞음                  →  새 학생
```

**이름은 판정에 쓰지 않는다.** 이름만 같은 것은 동명이인이라 물어봐야 소용이 없고,
같은 반에서 계속 걸린다. 이름이 틀렸어도 번호가 맞으면 걸리므로 오타는 그대로 잡힌다.

| 상황 | 번호 일치 | |
|---|---|---|
| 재업로드 | 둘 다 | 셋 다 같으니 **통과** |
| 학생번호 오타 | 학부모번호 | **묻는다** |
| 이름 오타 | 둘 다 | **묻는다** |
| 학부모번호 오타 | 학생번호 | **묻는다** |
| 형제 | 학부모번호 | **묻는다** — 형제일 수도, 남의 번호를 잘못 적었을 수도 |
| 동명이인 | 없음 | **안 묻는다** |

**대조키는 쓰지 않는다.** 그건 뒷4자리만 보는 지면 대조용이고, 계정 판정은 전체 번호로 본다.

**학년·학교는 저장만 하고 판정에 쓰지 않는다.** 같은 반이면 대부분 겹쳐서 신호가 되지 않는다.

### 2-4. 발송

```
엑셀 업로드 시작
   │  ← 이 구간은 확정되지 않는다. 나갔다 들어왔다 할 수 있다
   │     컬럼 매핑 · 학교 별칭 · 중복 확인 · 학부모 확인 · 교재 선택
   ▼
발송   결제선생 + 아이디 문자가 **함께** 나간다      ← 배치 완료
```

그 전까지는 아무것도 만들어지지 않는다. 아이디와 비밀번호는 임시로 들고 있을 뿐이고
PK 가 할당되지 않는다 — 학생 관리 화면에도 나타나지 않는다.
**문자가 나가야 실제 계정이 된다.**

#### 결제선생

**자동으로 나가지 않는다** — 보낼지 말지 정한다.

```
보낸다  →  ① 무엇을 청구할지 고른다   그 커리의 교재 중 · 전체/학생별
           ② 결제선생 문자           → 학부모에게만
           ③ 알림톡                  왜 청구했는지 · 결제선생으로 간다는 안내
```

**알림톡이 따로 나가는 이유**는 결제선생 문자만 받으면 무엇에 대한 청구인지 모르기
때문이다.

#### 계정 안내 — 같은 시점에 나간다

순서대로 나가는 것이 아니라 같이 나간다.

- **학부모에게 자녀가 둘이면 묶어서** 한 번에
- **비밀번호는 임시로** 만들고 LMS 에 들어가기 전에 반드시 바꾸게 한다 — 둘 다

  ```
  랜덤 8자리 · 0 · 1 · o · l 을 뺀다
  ```

  **헷갈리는 글자를 빼는 이유**는 알림톡으로 받아서 눈으로 보고 타이핑하기
  때문이다. `0`/`O`, `1`/`l` 이 섞이면 로그인이 안 되는데 왜 안 되는지 알 수 없다

- **비밀번호를 잊으면 Teacher 가 되돌린다** → 새 랜덤을 발급하고 다시 변경을
  강제한다. 학생·학부모가 스스로 복구하는 길은 두지 않는다 — 사람이 처리한다

**고려사항**

- **학생 전화번호가 없으면 학부모가 대신 받는다** — 학생 계정 정보까지 학부모 번호로
- **엑셀에 학생 번호와 학부모 번호가 같게 오면 학부모 번호로 본다**
- **이미 계정이 있으면 안내가 안 나간다**(학생·학부모 모두). 결제는 나간다 —
  계정은 한 번 만들면 끝이지만 교재는 수업마다 새로 사기 때문이다

  | 이 사람이 | 계정 안내 | 결제 |
  |---|---|---|
  | 처음 온다 | 나간다 | 나간다 |
  | 계정이 있다 | **안 나간다** | **나간다** |

- **계정이 있는데 다른 반이면 수강만 추가**한다. 커리가 달라도 결제는 똑같이 나간다
- **교재 선택은 전체 적용도 학생별 조정도 된다.** 1권을 이미 가진 학생에게 나머지만
  청구하는 자리가 여기다(1-6)
- **형제 합산은 구조가 필요하다.** 지금 `Order` 는 **학생 1명 + 교재 1종**이라,
  형제 둘 × 교재 2종이면 주문 4건에 청구서는 1건이어야 한다 — 청구서가 주문 여럿을
  덮는 층이 있어야 한다

### 2-5. 그 뒤 — 학생·결제 관리

#### 무엇을 샀는지 학생이 들고 있다

결제가 확인되면 그 학생이 어느 교재를 샀는지 목록으로 남는다.
반별 학생 관리 화면과 학생 상세 화면에서 보고 고친다.

#### 개별 발송 — 언제든 다시 보낼 수 있다

| 보낼 것 | |
|---|---|
| **아이디 안내** | **학부모·학생을 따로** 고른다 |
| **결제 요청** | 개별로 |

언제든 가능해야 한다. 문자를 못 받았다거나 번호를 고쳤다거나 하는 일이 계속 생긴다.

#### 결제 건은 개별로 다룬다

- 결제 내용이 **행으로** 보인다. 취소·환불된 건도 같은 행으로 남는다
- 건별로 **취소 · 환불**

#### 발송 내역이 학생마다 남는다

**알림톡·결제선생 발송 내역**이 학생별로 계속 보여야 하고, 어느 번호로 나갔는지도
남아야 한다. "안 받았다" 는 말이 계속 나오는데, 기록이 없으면 다시 보내는 것 말고
할 수 있는 일이 없고, 그러면 같은 문자가 두 번 가거나 정작 필요한 사람은 계속 못 받는다.

**고려사항**

- **오프라인으로 이미 받은 교재도 여기서 맞춘다**
- **일괄 적용이 된다** — "이 반 전원이 이 교재를 샀다" 를 한 번에. 결제가 우리 밖에서
  이뤄지는 경우가 있기 때문이다(2-7)
- **부분 환불은 전액 취소 + 재결제**다. 결제선생이 전액 취소만 지원한다.
  학부모에게는 취소 안내와 새 청구가 각각 나간다
- **결제 관리는 반 밖에서도 한다** — 반과 무관하게 전체를 필터로 훑는 화면.
  영상과 같은 결이다(1-7)
- 발송 내역을 읽는 기능은 이미 있다. **학생별로 묶어 보여 주는 자리가 없을 뿐이다**

### 2-6. 학생 상세 페이지

2-3 에서 "수정" 을 고르면 오는 곳이고, 학생에 대한 것이 여기 모여 있다.

| | |
|---|---|
| 학교 | |
| **학년** | 아래 승급 규칙 |
| **학생 번호** | 고칠 수 있다 → 아이디가 바뀐다 |
| **학부모 번호** | 고칠 수 있다 → 아이디가 바뀌고 청구도 다시 나간다 |
| 대조키 | 파생값 |
| 구입한 교재 | 2-5 |
| 발송 내역 | 2-5 |

여기서 전부 고칠 수 있다.

#### 학년은 다섯 뿐이고, 2월 마지막 날에 오른다

```
예비 고1  →  고1  →  고2  →  고3  →  N수  →  N수 (멈춤)
```

- 다섯 말고는 없다. 중3·중2 같은 것은 두지 않고 전부 `예비 고1` 로 통칭한다
- **2월 마지막 날에 자동으로 오른다** — 3월 새 학년이 시작되기 직전이다
- **N수는 더 오르지 않는다**

#### 번호를 고치면 아이디가 바뀐다

아이디가 뒷4자리에서 나오기 때문이다(2-3).

| 틀린 것 | 하는 일 |
|---|---|
| 학생 번호 | 아이디·비밀번호 재생성 → **학생 계정 안내 재발송** |
| 학부모 번호 | 아이디·비밀번호 재생성 → 안내 재발송 **+ 결제선생 청구 재발송** |

학부모 번호가 틀리면 **청구서가 엉뚱한 번호로 갔다는 뜻**이라 청구도 다시 나가야 한다.

**학생 정보(수강 이력·출결·성적)는 그대로 둔다.** 계정을 다시 만드는 것이 아니라
아이디와 비밀번호만 다시 만든다.

**고려사항**

- **대조키도 같이 바뀐다.** 다만 이미 낸 답안지는 그대로 둔다 — 대조는 낼 때 한 번
  끝난 일이고, 소급해 다시 돌리면 조교가 손으로 고른 것까지 뒤집힌다
- **대조키가 같은 학생이 한 반에 둘이면 자동으로 못 가른다.** 지면에서 오는 것은
  이름과 뒷4자리가 전부라 구분할 근거가 없다. **매번 사람이 지정한다** —
  조교가 고른 것을 기억해 재사용하는 방식은 검토했다가 버렸다(맞는 경우가 없고,
  겹칠 때 두 번째 학생의 답안지가 첫 번째에게 조용히 붙는다)

### 2-7. 장소마다 결제 방식이 다르다 (**대표 확인 필요**)

| 장소 | 교재값을 누가 받나 |
|---|---|
| **미래탐구** | 결제선생 |
| **러셀** | **학원이 따로 받는다** — 결제선생이 나가면 안 된다 |

둘 다 정해진 기간 전에 계정은 만들어 준다. 차이는 결제뿐이다.

- 보낼지 말지를 고르는 자리는 이미 있다(2-4) — 문제는 **장소로 자동 판정할지**,
  매번 사람이 고를지다
- 러셀은 결제가 우리 밖에서 끝나므로 **교재를 샀다는 표시를 일괄로** 찍어야 한다(2-5)

---

## 3. 수업

수업이 도는 동안. 주차 하나 안에 출결표와 OMR 이 같이 있고, OMR 이 출결을 만든다.

```
① 반별 관리 열기     누가 무엇을 결제했나 → 교재 배분
② 모의고사 채점      OMR → 대조 → 조교 보정 → 성적표 · 반 평균
③ 출결               대조된 학생은 자동으로 출석
④ 영상 지급          조교가 누르면 출석자에게 나간다
⑤ 끝                수업을 닫는다
```

---

### 3-1. 반별 관리 페이지

조교가 연다. §2 와 같은 화면이고, 여기서 보는 것은 누가 무엇을 결제했는가다.
그에 따라 교재를 배분한다 — **미래탐구에서만** 한다(러셀은 학원이 따로 받으므로 2-7).

---

### 3-2. 주차 하나 = 출결표 + OMR

주차는 항상 열려 있다. 종료 체크를 할 수 있지만 **종료해도 안의 데이터는 고칠 수 있다.**

```
3주차
  ├ 출결표
  └ OMR        ← 고치면 출결표가 따라온다
```

**OMR → 출결표는 흐르고, 반대는 없다.** 출결을 손으로 고쳐도 OMR 은 건드리지 않는다.

---

### 3-3. 모의고사 채점 — OMR

#### 대조는 세 단계로 좁힌다

```
① 대조키           {이름}{뒷4자리} 로 찾는다
② 반 안에서        이름·전화 중 하나가 비면 이 반의 명단으로 찾는다
                      → 찾아도 "매핑 불확실" 로 표시한다
③ 조교             그래도 못 찾으면 사람이 고른다
```

②로 찾은 것은 확실하지 않다. 반 안에서 좁혔을 뿐이라 틀릴 수 있고, 틀리면 다른 학생의
성적에 붙는다.

#### 확실하지 않은 것은 위로 올린다

| 무엇이 불확실한가 | |
|---|---|
| **마킹** | `x` 로 표시한 것 · 체크로 표시한 것 · 희미한 것 |
| **이름·전화** | 읽히지 않았거나 빈칸 |
| **매핑** | 위 ②로 찾은 것 |

#### 성적표와 반 평균은 그래도 나온다

정보가 덜 찼어도 성적표는 만들고, 이 모의고사의 반 평균을 낸다.

**고려사항**

- **명단에 없는 사람이 시험을 봤을 수 있다.** 조교가 있는 정보만으로 학생을 등록하고,
  나머지는 나중에 채운다(관리 기록카드를 받아서). 아이디·결제선생은 수동으로 내보낸다
- **OMR 은 다시 돌리면 덮어쓴다.** 그전 행을 다 지우고 새로 만들며 성적도 다시 쓴다
- **읽는 엔진은 이미 서 있다** — 마킹이 희미하면 장째로 사람에게 넘기는 게이트가 있고,
  대조 결과도 여섯 갈래(`정상`·`부분`·`불일치`·`미존재`·`중복`·`비정상`)로 나뉜다.
  없는 것은 화면이다
- **아직 안 풀린 것 넷**

  | | |
  |---|---|
  | 평가원 모의고사 설문조사 | **OMR 로 읽되 이름·번호를 안 적으면 학생에 안 붙는다** — 조교가 집계만 본다("6월 평균은 이랬다"). 이름·번호를 적었으면 학생에 붙는다 |
  | 설문조사의 전화번호가 5자리 | 그 자리는 **수험번호**다. 지금 설계는 전화 4자리 전제 |
  | 내년부터 25문제 | 지금 **20문제 기준** |
  | 성적표 포맷 | 무엇을 어떤 모양으로 낼지 미정 |

  **수험번호가 대조키를 흔든다** — 지면에서 오는 숫자가 전화번호가 아니면 대조 방식이
  달라진다. 설문조사를 학생에 붙이려면 OMR 읽기를 고쳐야 한다

---

### 3-4. 출결 상태

| 상태 | 어떻게 되나 |
|---|---|
| **결석** | **기본값이다.** 아무 일도 없으면 결석이다 |
| **출석** | OMR 이 대조되면 자동으로 바뀐다. **시험을 안 보는 학생도 있으므로** 손으로도 바꾼다 |
| **퇴원** | 조교가 직접 처리한다 |
| **동보** | 결석분의 **그 주 보강 영상**을 신청하면 자동으로 바뀐다 |
| **현보** | 이 반 학생이 아닌데 **여기로 보강을 온** 경우 |

#### 동보

```
학생 또는 학부모가 신청  →  자동 지급  →  일주일 뒤 회수
```

결석한 그 주차의 영상을 받는다.

- **학생과 학부모 둘 다** 신청할 수 있다 — 동보만 그렇다(클리닉은 학생만)
- **승인이 없다.** 결석했다는 근거가 이미 출결에 있으므로 사람이 한 번 더 볼 것이 없다
- 결석 근거가 없으면 신청이 성립하지 않는다

> **지금 시스템과 다르다.** 지금은 동보도 승인을 거치게 돼 있다.
> 이 문서가 기준이므로 그 단계를 걷어내야 한다(부록).

#### 현보

**조교가 지정한다.** 학생이 신청하는 것이 아니다. 두 갈래로 생긴다.

```
시험을 봤다   OMR 이 들어왔는데 이 반 명단에 없다
              → 조교가 판단한다: 새 학생인가, 다른 반 학생이 온 것인가
              → 다른 반이면 현보로 찍는다

시험을 안 봤다  조교가 출결표에 직접 더한다
```

**첫 번째가 흔하다.** OMR 대조가 실패하는 이유 중 하나가 현보이기 때문이다 —
명단에 없는 이름이 나오면 새 학생일 수도 있고 남의 반 학생일 수도 있어서
조교가 갈라 준다(3-3).

현보로 받는 순간부터 그 한 주 동안 이 반의 학생이 된다.

| | |
|---|---|
| 영상 | 이 시점부터 나가고 **일주일 뒤 회수** |
| 클리닉 | **이 반의 평균**을 따른다 |
| 클리닉 신청 | **그 슬롯 전날까지** — 다른 학생과 같은 규칙이다 |

**원래 반이 어디인지는 규칙에 쓰지 않는다.** 클리닉 슬롯마다 자기 날짜가 있고 신청은 그
전날까지다 — 현보든 아니든 같다.

#### 출결표에 원래 반이 보여야 한다

규칙에는 안 쓰지만 화면에는 보여야 한다.

```
출결표 · 목 6.5 대치러셀 · 3주차
  김하늘        출석
  이서준        출석
  박지우  현보  출석    ← 원래 화 6.5 대치러셀
```

조교가 그 자리에서 왜 이 학생이 여기 있는지 알아야 하기 때문이다. 명단에 없던
이름이 갑자기 있으면 잘못 들어온 것으로 보인다.

점수는 이 반 평균에 넣는다. 시험을 봤으면 다른 학생과 똑같이 센다.

---

### 3-5. 영상 지급

출결표가 어느 정도 정리되면 조교가 "동영상 지급" 을 누른다.
그러면 **출석한 학생에게 자동으로** 나간다.

자동으로 나가지 않고 사람이 누르는 이유는, 출결이 아직 정리 중일 때 나가면 결석으로
남아 있는 학생이 받지 못하기 때문이다.

**마감 뒤에 출결이 바뀌면 그 학생은 수동으로 준다**(3-11). 화면이 "아직 못 받았다" 로
표시하고 조교가 버튼을 누른다 — 다시 일괄로 돌리지 않는다. 이미 받은 학생의 만료를
건드리지 않기 위해서다.

---

### 3-6. 수업 중에 교재가 늘어날 수 있다

4주차·5주차에 자사 모의고사 같은 것을 새로 팔 수 있다. 조교가 미는 것이 아니라
**학생이 LMS 에서 직접 신청**한다.

```
학생이 신청  →  결제선생이 나간다  →  결제 완료  →  "구입한 교재" 에 뜬다
```

§2 의 등록 배치와 다른 점은 학생이 시작한다는 것뿐이다.
**표지 사진이 여기서 쓰인다**(1-6).

---

### 3-7. 클리닉과 영상

시점·조건은 코드에 있고 여기서 다시 정하지 않는다.

| | |
|---|---|
| **클리닉 대상** | 출석 + 시험 응시 + **평균 미달**. 기준점은 관리자 컷, 없으면 그 시험 전체 평균 |
| **클리닉 신청** | **학생만.** 학부모는 못 한다. **승인을 거친다** — 동보와 반대다 |
| **클리닉 마감** | **그 슬롯 전날까지.** 현보도 같다 |
| **클리닉 정지** | **노쇼 2회면 못 한다** — 잡아 놓고 안 오면 그 자리가 통째로 버려진다 |
| **영상 부여·회수** | **출결 입력 시점** 기준 — 넣고 얼마 뒤 부여(값 미정), 부여 + 일주일에 회수 |

**동보는 자동, 클리닉은 승인**이다. 동보는 결석이라는 사실이 이미 확정돼 있어 더 볼 것이
없지만, 클리닉은 자리와 시간을 잡는 일이라 조교가 배정해야 한다.

**고려사항**

- **노쇼 2회면 클리닉을 못 한다.** 자리는 한정돼 있고, 잡아 놓고 안 오면 그 자리를
  다른 학생이 못 쓴다. 노쇼 누적과 정지 표시는 이미 자리가 있다(부록)
- **5분 전 안내는 예약 발송으로 한다.** 배정하는 시점에 업체에 예약을 걸어 두면 업체가
  정확한 시각에 보낸다 — 우리 쪽에 주기 작업이 필요 없다. 취소되면 예약도 취소한다
- **신청 시점에는 알리지 않는다.** 학생이 직접 누른 일이라 이미 안다

---

### 3-8. 새 학생은 계속 생긴다

3-3 에서처럼 **수업 중에도 학생이 늘어난다.**

- **언제든 아이디 안내·결제선생을 보낼 수 있다**(2-5 의 개별 발송과 같다)
- 한 번도 안 보낸 학생은 일괄로도 보낸다
- 정보를 고친 뒤 다시 보낼 수 있다
- **어느 번호로 나갔는지**가 발송 내역에 남아야 한다

---

### 3-9. 반 이동

조교가 학생의 반을 옮길 수 있다.

- **옮기는 즉시 그 반의 룰**을 적용받는다
- 이미 나간 영상은 그대로 간다 — 회수는 지급 시점 + 일주일이라 반과 무관하다
- 이미 잡힌 클리닉도 그대로다 — 슬롯에 붙은 것이라 반이 바뀌어도 움직이지 않는다

---

### 3-10. 수업 닫기

| | |
|---|---|
| 드롭다운·새 등록 | **사라진다** |
| 과거 기록(출결·성적·영상 권한·결제) | **그대로 조회된다** |

지난 기록이 그 반을 참조하고 있다. 지우면 "어느 반의 3주차 결석" 이었는지를 알 수 없게 된다.
교재의 `Active` 와 같은 방식이고, 지금 시스템도 이미 그렇게 하고 있다(부록).

---

### 3-11. 알림톡이 나가는 시점

지금까지의 흐름에서 **반드시 나가야 하는 것만** 추린 여섯이다.

| # | 언제 | 누구에게 | 왜 |
|---|---|---|---|
| 1 | **계정 발급**(2-4) | 학생 · 학부모 | 아이디·임시 비밀번호를 모르면 못 들어온다. 자녀가 둘이면 학부모에게 묶어서 |
| 2 | **교재 청구**(2-4) | 학부모 | 결제선생 문자만 받으면 **무엇에 대한 청구인지 모른다** |
| 3 | **결제 취소·환불**(2-5) | 학부모 | **업체가 알리지 않는다.** 우리가 안 보내면 아무도 모른다 |
| 4 | **출결 마감**(아래) | 학생 · 학부모 | 그 주에 있었던 일을 한 번에 전한다 |
| 5 | **클리닉 확정**(3-7) | 학생 · 학부모 | 승인제라 결과를 알려야 온다 (신청은 학생만 하지만 결과는 둘 다 본다) |
| 6 | **클리닉 5분 전**(3-7) | 학생 | 잊고 안 오는 것을 막는다 |

**신청했을 때는 안 보낸다** — 학생이 직접 한 일이라 이미 안다. 보내는 것은 확정부터다.

**개별 재발송**(2-5)은 1·2 를 다시 보내는 것이라 새 시점이 아니다.

#### 4 — 출결 마감 통지

**조교가 `출결 마감` 을 누르면 나간다.** 자동이 아니다 — 채점이 끝났는지는 사람이 판단한다.

```
수업 당일   수업 · OMR 수거 · 워크북 수거
   ↓
조교        OMR 채점 → 출결 확정 → 영상 지급
   ↓
[출결 마감] ← 누르면 통지가 나간다
```

**누르면 그 반 전체에 자동으로 나간다.** 한 명씩 고르는 것이 아니다.

**마감을 눌러도 출결표는 계속 고칠 수 있다.** 마감은 *"이제 통지를 보낸다"* 는 뜻이지
*"더 못 고친다"* 는 뜻이 아니다.

#### 마감이 여는 것

마감을 누르면 그 주에 대해 나갈 수 있는 것이 열린다.

```
영상 발송 · 문자 발송 · 성적표
```

#### 마감 뒤에는 수동으로 보낸다

출결표는 계속 고칠 수 있다. **다만 그 뒤로는 자동으로 나가는 것이 없다.**

대신 **화면이 표시해 준다** — 누구에게 무엇이 안 나갔는지, 누가 바뀌었는지.

```
3주차 · 목 6.5 대치러셀            [마감됨]
  김하늘   출석                     ✓ 발송
  이서준   결석 → 출석  (수정됨)     ⚠ 재발송 필요   [보내기]
  박지우   출석                     ⚠ 미발송        [보내기]
```

조교가 버튼을 눌러 보낸다. 오타 하나 고칠 때마다 문자가 나가면 안 되고,
결석↔출석처럼 **학부모가 알아야 하는 변화**만 골라 보내야 하기 때문이다.

**고려사항**

- **`출결 마감` 이라는 이름이 맞는지 미정** — 고칠 수 있는데 마감이라 부르는 것
- **언제 누르는지도 미정** — 당일일 수도, 다음날일 수도 있다

성적표는 이렇게 나간다.

| | |
|---|---|
| **오프라인** | 지면으로 뽑아 나눠 준다 |
| **온라인** | 알림톡에 **링크**로 실린다 — 문자에 성적을 적는 것이 아니다 |

그 링크를 보내면서 그 주에 관한 것을 함께 전한다.

| 담기는 것 | |
|---|---|
| **출결** | 오늘 왔다 / 안 왔다 |
| **성적** | 이번 회차 결과 |
| **워크북** | 냈는지 · 수행도 |
| **클리닉** | 대상이면 "이렇게 신청한다" |
| **동보** | 결석이면 "여기서 보강 영상을 신청한다" |

같은 주 이야기를 다섯 번 나눠 보내면 학부모는 무엇이 새 소식인지 모르고, 정작 봐야 할
것(결석·클리닉 대상)이 묻힌다.

받는 사람에 따라 내용이 갈린다 — 출석했으면 동보 안내가 없고, 클리닉 대상이 아니면
클리닉 줄이 없다. 카카오 템플릿은 문구가 고정되므로 **이 갈래를 템플릿 몇 개로
표현할지가 8-17 에서 정해져야 한다.**

**링크라서 갈래가 줄어든다.** 점수·과목별 결과처럼 사람마다 다른 것은 링크 너머에
있으므로 템플릿 문구에 안 들어간다. 문자에 남는 것은 출결·클리닉·동보처럼 있고
없고가 갈리는 몇 줄뿐이다.

**고려사항**

- **링크는 로그인해야 열린다.** 성적은 개인정보이므로 주소만으로는 못 본다.
  LMS 에 들어가서 보는 것과 같은 화면이고, 문자의 링크는 그리로 데려다줄 뿐이다

#### 일부러 안 보내는 것

| | 왜 |
|---|---|
| 영상 지급 | 학생이 LMS 에서 바로 본다. 매주 문자가 가면 소음이 된다 |
| 동보 지급 | 학생이 **직접 신청**하고 자동으로 나간다 — 자기가 한 일이다 |
| 결석 안내(별도) | **전화로 한다**(3-12). 주차 마감 통지에 "안 왔다" 가 들어가지만, 그것과 별개로 조교가 건다 |

**고려사항**

- **템플릿은 사전 승인제다.** 카카오가 문구를 먼저 심사하므로 문구가 확정돼야
  개발이 시작된다
- **위 여섯이 최종 목록이 아니다.** PRD 8-17 이 전체 목록을 들고 있고, 그것이 오면
  여기와 대조해야 한다

| | 언제 | 지금 코드 |

| **워크북 처리** | 수업 **당일** | 사진 업로드·매칭·보정이 이미 서 있다 |

## 4. 학생·학부모가 보는 것

§1~3 은 Teacher 쪽 이야기고, 여기는 **받는 쪽**이 무엇을 보고 무엇을 하는지다.

학부모가 보는 것은 학생도 다 본다. 학생 쪽이 더 넓고, 학부모 쪽은 그 부분집합에
자녀 선택이 붙는다.

---

### 4-1. 학생 — 보는 것 + 하는 것

| 하는 것 | |
|---|---|
| **동보 신청** | 결석한 주의 보강 영상. 신청하면 **자동 지급**(3-4) |
| **클리닉 신청** | 대상일 때. **승인을 거친다**(3-7). **학생만 할 수 있다** |
| **교재 신청** | 수업 중에 추가로 파는 것(3-6) |
| **영상 시청** | 권한이 있는 주차의 영상 |

| 보는 것 | |
|---|---|
| **이번 주** | 무엇을 하는 주인지 |
| **출결** | 내 출결 |
| **성적표** | 회차별 + **누적** |
| **워크북** | 낸 것 + 수행도, **누적** |

---

### 4-2. 학부모 — 보는 것만

하는 것은 없고, 자녀가 무엇을 하고 있는지 확인하는 쪽이다.

| | |
|---|---|
| **이번 주** | 자녀가 무엇을 하는 주인지 |
| **출결** | 왔는지 안 왔는지 |
| **성적표** | 회차별 + **누적** |
| **워크북** | 낸 것 + 수행도, **누적** |

자녀가 둘 이상이면 드롭다운으로 고른다(2-3).

**고려사항**

- **동보·현보 같은 상태가 그대로 보인다.** 학부모가 "왜 이 주는 동보인가" 를 알 수
  있어야 하고, 그 말이 화면에서 이해돼야 한다
- **동보 신청만 학부모도 할 수 있다**(3-4). 그것 하나가 예외이고, **클리닉은 학생만** 신청한다

---

### 4-3. 성적 분석

점수만 보여 주면 알 수 있는 것이 적어서, 어디가 약한지까지 나와야 한다.

| 나와야 하는 것 | |
|---|---|
| **단원별 성취** | 대단원·중단원에서 어디가 무너지는지 |
| **누적 추이** | 회차를 거치며 나아지는지 |
| **오답마다 학습가이드** | 그리고 그 가이드가 **영상으로 이어진다** |

재료는 이미 있다. 문항마다 대단원·중단원·테마·오답 학습가이드·가이드 영상이
붙어 있고, 단원별 점수는 그것들로 바로 계산된다.

클리닉·동보와도 이어진다. 약점이 보이면 클리닉에서 무엇을 할지가 정해지고, 가이드
영상도 그 자리에서 연결된다.

**고려사항**

- **만들 수 없는 것은 설계에 넣지 않는다.** 시중 성적표의 절반 이상이 전국 표본을 쓰는데
  (표준점수·백분위·등급·상위 %·지원가능대학), 우리에겐 그 표본이 없고 반 평균으로
  대체되지도 않는다 — 반 30명은 표본이 아니다
- **화면 설계는 여기서 하지 않는다.** 참고 자료와 분석은 따로 있다(2026-08-16)
- **OMR 포맷이 확정돼야 한다.** 분석의 재료가 지면에서 오기 때문이다 —
  25문제 전환(3-3), 추가 마킹란, 설문조사 처리가 여기에 걸린다

## 부록 — 지금 시스템과의 차이

여기부터는 개발용이다. 위 흐름을 지금 시스템이 얼마나 담을 수 있는지 실사한 것이고
(2026-08-12), 흐름 자체를 이해하는 데는 필요하지 않다.

결론부터 적으면, 이 흐름은 현재 구조로 표현할 수 없다. 옮겨야 할 것:

| | 지금 | 필요한 것 |
|---|---|---|
| **반** | `CourseEnrollment.class_name` **문자열**(+ `Student.current_class` 에 또 한 벌) | 엔티티. 이름·개강일·학생·주차 날짜를 갖는다 |
| **주차 내용** | `CourseWeek` 가 **강좌**에 매달림 | **커리**에 매달린다 — 반들이 나눠 쓴다 |
| **주차 일정** | `CourseWeek.start_date` 가 **강좌마다 하나뿐**이라 반별로 다를 수 없다 | **반**이 주차마다 날짜를 갖는다. 자동 채움 + 수정(앞을 고치면 뒤가 따라옴, 1-3) |
| **날짜가 하는 일** | `release_at` 이 날짜로 공개를 발동한다 | **아무것도 발동시키지 않는다** — 부여·회수·잠금은 입력 시점 기준(1-4) |
| **회차** | `ClassSession` 이 **어느 반인지 모른다** — 날짜와 학년만 있다 | 반 + 주차번호로 잡힌다. 날짜는 "언제 넣었나" 일 뿐 일정이 아니다 |
| **구분·과목** | 없음. `Course.name` 한 칸에 뭉개 넣음 | 값집합 두 개 |
| **커리** | 없음 — `Course` 가 과목과 커리를 겸한다 | 과목과 반 사이의 층. 교재가 여기 붙는다 |
| **교재** | `payments.Product` 가 어디에도 안 붙어 있다 | **커리**에 붙는다 + 표지 사진 · 세트/낱개 표시(1-6) |
| **총주차** | 없음 | **커리**의 속성. 반은 덜 하려면 그 칸을 비워 둔다 |
| **잠금** | 없음 — 아무 때나 고쳐진다 | **첫 기록이 생기면** 정체성 필드가 잠긴다 |

- 반이 문자열이라 학생 명부 검색이 부분일치다. 코드 주석이 이유를 이렇게 적어 두었다 —
  *"반 이름 표기 흔들림 허용"*. 이미 흔들리고 있다는 뜻이다
- **동보에 승인 단계가 있다** — 이 문서는 자동 지급이므로 걷어내야 한다(3-4)
- **노쇼 누적·클리닉 정지**는 이미 자리가 있다(3-7)
- **선지 번호와 추가 마킹란**도 이미 저장할 자리가 있다(4-3)
- **날짜로 공개를 발동하는 자리**가 남아 있다 — 날짜는 아무것도 발동시키지 않아야 한다(1-4)
- `week_no`·`CourseWeek` 를 참조하는 파일이 **18개**다. 영상 권한(`video_admin`)·게시판·
  출결·홈 화면이 전부 걸린다
- **지금이 제일 싼 시점이다** — 운영 데이터가 데모뿐이고 아직 오픈 전이다.
  오픈 후에는 실제 출결·영상 권한을 이관해야 한다

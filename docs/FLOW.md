이 문서가 기준이고, 다른 문서와 어긋나면 여기가 맞다.

## 1. 수업 생성

첫 수업을 열기까지. 만드는 단위는 **`반`** 이고, 반 하나가 수업 묶음 하나가 된다.

---

### 1-1. 층 구조

```
과목구분        수능 · 내신
  └ 과목        통합과학
      └ 커리    2026 여름 N제        ← 무엇을 가르치는가
          ├ 반  목 6.5 대치러셀      ← 누가 · 언제 듣는가
          └ 반  화 6.5 대치러셀
               └ 학생
```

| | 담는 것 |
|---|---|
| **커리** | 가르치는 내용. **주차 · 영상 · 총주차 · 교재** |
| **반** | **학생 · 출결 · 성적 · 주차 날짜** |

**학생 ↔ 반은 N:M 이다.** 수능 반과 내신 반을 같이 듣는 학생이 있을 수 있다.

**주 1회라 주차와 수업 회차가 1:1 이다.** 주에 두 번 만나는 반이 생기면 회차로 센다.

왜 갈랐나. 같은 `2026 여름 N제` 를 목반과 화반이 같이 듣는다. 내용을 반마다 적으면
같은 것을 두 벌 쓰게 되고, 한쪽만 고쳐서 어긋난다. 반대로 일정을 커리에 두면 한 반이
휴강했을 때 다른 반까지 밀린다.

---

### 1-2. 만들기

| 층 | 넣는 방식 |
|---|---|
| **과목구분** | 드롭다운. **신규 입력 없음** — `수능`·`내신` 둘 |
| **과목** | 드롭다운. **신규 입력 가능** |
| **커리** | 자유 입력 |
| **반** | 자유 입력 |

| 커리 | | | 반 | |
|---|---|---|---|---|
| **커리명** | `2026 여름 N제` | | **수강반명** | `목 6.5 대치러셀` |
| **총주차** | `10` | | **개강일** | `2026-09-04` |
| **클리닉 시간대** | `15:00–21:00` | | **문자 포맷** | 반마다 고른다 |

**요일은 개강일에서 얻는다.** 시간·장소는 반 이름에 들어 있고 시스템이 파싱하지 않는다.

**커리와 반은 한 화면에서 만든다.** 커리만 있고 반이 없으면 아무도 그 수업을 듣지
않으니 쓸 일이 없다. 이미 있는 커리에 반을 더하는 것도 같은 화면에서 된다.

**문자 포맷은 반을 만들 때 드롭다운으로 고른다.** 이 반에서 무엇이 나갈지를
거기서 정하고, 그게 전부다(3-11).

**클리닉 시간대는 커리가 갖는다.** 한 시간 단위로 슬롯이 서고, 언제든 고칠 수 있다 —
고친 날 이후부터만 적용된다(3-7).

#### 구분 ↔ 과목

| 구분 | 과목 |
|---|---|
| **수능** | 통합과학 |
| **내신** | 일반선택 생명과학 |
| | 진로선택 생명과학 — 세포와 물질대사 |
| | 진로선택 생명과학 — 생물의 유전 |

---

### 1-3. 캘린더

**반을 만들면 커리의 총주차만큼 날짜가 자동으로 채워진다.** 개강일에서 주 단위로 잡는다.

```
커리 총주차 10 · 개강일 9/4  →  1주차 9/4 · 2주차 9/11 · … · 10주차 11/6
```

**주차를 더하고 지우는 것은 반에서만 한다.** 9주차에서 끝내는 반은 10주차를 지우고,
더 하는 반은 11주차를 더한다. **커리의 총주차는 안 바뀐다** — 한 반을 고쳐도 다른 반은
그대로다.

**지울 수 있는 것은 마지막 주차뿐이고, 기록이 붙었으면 못 지운다.** 가운데를 지우면
구멍을 메우려고 번호를 다시 매겨야 하는데 그건 아래에서 기각했다. 출결·OMR·성적이
붙은 주차는 지우는 순간 그 기록이 같이 사라진다.

**주차마다 코멘트를 적을 수 있다.** 그 주에 무엇을 하는지를 한 줄로 남기는 자리고,
학부모가 자녀 화면에서 본다(4-2). 언제든 고칠 수 있다.

**코멘트는 커리가 갖는다.** 그 주에 무엇을 하는지는 내용이고, 내용은 커리 것이다
(1-1). 같은 커리를 듣는 반들이 같은 것을 배우므로 한 번 적으면 다 본다.

**반이 혼자 더한 주차는 적을 자리가 없다** — 커리에 그 주차가 없기 때문이다.

그 뒤로는 조교가 각 주차 날짜를 고친다. 앞을 고치면 뒤가 따라온다.

```
3주차를 9/18 → 9/25 로 고치면  →  4주차 이후도 일주일씩 밀린다
```

휴강이 그런 모양이기 때문이다 — 그 주만 건너뛰는 것이 아니라 그 주부터 뒤가 다 늦어진다.
별도의 "밀기" 버튼은 없다. 날짜를 고치는 것이 미는 방법이다.

움직이는 것은 날짜뿐이고 번호는 그대로다.

| | |
|---|---|
| **채택** | `3주차` 는 계속 `3주차` 이고 날짜만 뒤로 간다 |
| ~~기각~~ | ~~그 주를 비우고 다음 수업이 4주차가 된다~~ |

출결·성적·영상 권한이 주차 번호로 붙기 때문이다. 번호가 흔들리면 이미 쌓인 기록이
다른 것을 가리키게 된다 — 어제 "3주차 결석" 으로 남긴 것이 오늘은 다른 수업이 된다.

---

### 1-4. 날짜는 보여 주기용이다

주차에 날짜가 있지만 그 날짜가 무엇을 발동시키지는 않는다.

| 무엇 | 무엇을 기준으로 |
|---|---|
| 영상 부여 | **`출결 확정` 을 누를 때** |
| 영상 회수 | **부여 + 일주일** |
| 동보 · 현보 | **지급 시점 + 일주일** |
| 클리닉 신청 마감 | **그 슬롯 전날** — 슬롯은 자기 날짜를 갖는다 |

왜. 출결도 OMR 도 영상 지급도 **조교가 누르는 순간** 일어난다. 날짜를 시계로 쓰면
휴강해서 날짜를 안 고친 반에서 영상이 엉뚱한 때 나가거나 회수된다.

날짜는 사람이 보라고 있다 — 조교가 몇 주차가 언제인지 알고, 학생·학부모 화면에
일정이 뜬다.

---

### 1-5. 잠기는 것은 없다

**기록이 쌓인 뒤에도 다 고칠 수 있다.** 반 이름도, 개강일도, 구분·과목도.

잠금은 원래 **반이 문자열이었기 때문에** 필요했다. 출결이 `목 6.5 대치러셀` 이라는
글자에 붙어 있으면 그 글자를 고치는 순간 지난 기록이 무엇에 대한 것인지 모호해진다.
반이 엔티티가 되면서 그 이유가 사라졌다 — 기록은 반을 가리키고, 이름은 그 반의
속성일 뿐이라 이름을 바꿔도 가리키는 대상이 안 변한다.

**커리 총주차도 안 잠근다.** 주차를 더하고 지우는 것은 반에서 하므로(1-3)
커리 총주차는 애초에 반의 주차 수를 정하지 않는다.

---

### 1-6. 교재 — 커리에 붙는다

**반별 교재는 없다.** 같은 커리를 듣는 반은 같은 교재를 쓴다.

```
2026 여름 N제 세트    세트    ← 상품
N제 1권               낱개    ← 상품
N제 2권               낱개    ← 상품
N제 3권               낱개    ← 상품
```

| 교재가 갖는 것 | |
|---|---|
| 이름 · 가격 | |
| **표지 사진** | |
| Active | 판매 종료를 삭제가 아니라 끄기로 |

**묶음과 낱개를 둘 다 등록한다.** 대부분은 세트로 사지만 1권을 이미 가진 학생이
있고, 그 학생에게는 나머지 2권만 청구해야 한다. 세트만 등록하면 그 청구를 만들 수 없고,
낱개만 등록하면 세트로 사는 대부분이 세 줄로 쪼개진다.

**고려사항**

- **포함 관계는 DB 에 넣지 않는다.** `세트`·`낱개` 표시만 두고, 조교가 세트에 무엇이
  들었는지 안다고 전제한다.
  **감수하는 것**: 세트와 그 안의 낱권을 같이 청구해도 시스템이 막지 않는다

---

### 1-7. 영상은 커리에 붙는다

관리자 화면이 갈려야 하는 축이 여기서 나온다.

| 축 | 무엇 | 왜 |
|---|---|---|
| **커리의 일** | **영상** | 내용이라 그 커리를 듣는 반이 다 같이 쓴다 |
| **반의 일** | **출결 · OMR · 클리닉 · 메시징** | 반마다 다르다 |

**매주 올리고, 올릴 때 자리를 정한다.** 한꺼번에 올리지 않는다 — 매주 찍어서 올리고
그때마다 어느 커리의 몇 주차인지 지정한다. 그 지정은 나중에 안 바뀐다.
**한 주차의 영상은 하나가 아니라 n개다.**

**반마다 어느 영상을 내보낼지 고칠 수 있다.** `N주차 → N주차` 가 기본값이지만 고정은
아니다 — 진도가 앞뒤로 갈 수 있다.

```
기본      반 3주차  →  커리 3주차 영상들
당겨오기  반 3주차  →  커리 4주차 영상들
섞기      반 3주차  →  3주차 2개 + 4주차 1개
```

권한은 반에서 나온다. 영상 자체는 커리 것이지만 누가 볼 수 있는가는 출결이 정한다.
영상 권한은 두 축이 만나는 자리다.

## 2. 학생 등록

```
① 명단이 온다        학원이 주는 엑셀 · 조교가 반을 고른다
② 엑셀 처리          컬럼·학교 이름을 맞춘다. 모르면 조교에게 묻는다
③ 아이디 생성        대조키 → 아이디. 중복이면 묻는다
④ 발송               결제선생 + 아이디 문자가 함께 나간다   ← 배치 완료
⑤ 그 뒤              구입 목록 · 개별 발송 · 결제 관리
```

---

### 2-1. 명단이 온다

학원에서 엑셀을 받는다. **시점을 정해 두지 않는다** — 엑셀이 올 때마다 하고,
수업이 시작된 뒤에도 온다(3-8).

| 이름 | 학교 | 학년 | 학생 핸드폰 | 학부모 핸드폰 |
|---|---|---|---|---|

**조교가 반을 골라서 등록한다.** 파일 자체에는 어느 반인지가 없다.

**두 번째부터는 그 배치에 든 학생만 걸린다.** 이미 있는 학생에게 계정 안내가 다시
가지 않고(2-4), 청구도 이번에 올린 명단에만 나간다.

---

### 2-2. 엑셀 처리

우리가 만든 서식이 아니라 **학원이 주는 파일**이다. 같은 뜻인데 매번 다르게 온다.
파일을 못 읽으면 계정도 청구도 시작되지 않는다.

```
① 정규화     한글 유니코드 정규화(NFC) · 공백 · 대소문자 · 전화번호
                 → 눈에 같은 값이 실제로 같아진다
② 자동 매칭   아는 변형은 시스템이 맞춘다
                 컬럼:  학생이름 · 성명 · 이름     → 이름
                 학교:  숙명여고 · 숙대부속고등학교 → 숙명여자고등학교
③ 조교       모르는 것이 남으면 사람이 지정한다
```

변형을 미리 다 알 수는 없으므로 ③이 필요하다. **조교가 한 번 답한 것은 다시 묻지 않는다.**

| 무엇이 낯설 때 | 조교가 하는 일 | 다음번에는 |
|---|---|---|
| **컬럼 이름** | "이 열은 무엇입니까" → `학생 핸드폰` 으로 지정 | **별칭표에 남는다** |
| **학교 이름** | 새 학교로 등록하거나 기존 학교의 **다른 이름**으로 붙인다 | **별칭표에 남는다** |

별칭표는 둘이고, 둘 다 새로 만들어야 한다.

```
컬럼 별칭표    이름       ← 성명 · 학생이름 · 학생 성명 · …
               학생 핸드폰 ← 학생HP · 학생 연락처 · 학생 전화 · …

학교 별칭표    숙명여자고등학교 ← 숙명고 · 숙명여고 · 숙대부속고등학교 · 숙명 여고
```

**학원별로 나누지 않는다.** 어느 학원이 준 파일이든 같은 표를 본다 — `성명` 은 어디서
와도 이름이다.

**고려사항**

- **전화번호는 정규화한다.** 계정 판정이 번호로만 이뤄지므로(2-3) 여기가 틀리면
  판정도 어긋난다

  | | |
  |---|---|
  | `-` · 공백 · 괄호 | 뗀다 |
  | **앞자리 `0` 이 사라진 것** | 되살린다 — **엑셀이 전화번호를 숫자로 읽으면 `010…` 이 `10…` 이 된다** |
  | `+82` | `0` 으로 바꾼다 |

  앞자리 `0` 이 제일 자주 문제가 된다. 서식을 텍스트로 안 잡고 저장한 파일은 전화번호가
  한 자리씩 밀려 오는데, 눈으로는 잘 안 보인다

- **학부모 번호는 휴대폰이다.** `070`·`02` 로 오는 경우는 없다(2026-08-19 확인).
  그래서 앞자리 `0` 복원을 `10`+8자리 한 모양에만 건다 — 그 모양은 휴대폰밖에 없어
  오판이 안 나고, 다른 자릿수는 건드리지 않는다

---

### 2-3. 아이디 생성

```
대조키   {이름}{전화 뒷4자리}       김민준1234    겹칠 수 있다   지면(OMR·워크북)이 쓴다
아이디   대조키 + a·b·c·d           김민준1234b   유일          로그인이 쓴다 (= 원번)
```

- **뒷4자리는 학생 번호**, 없으면 학부모 번호
- **아이디가 시스템상 원번**이다. 둘은 같은 값이다
- 겹치면 다음 사람부터 `a`·`b`·`c`·`d`. **`p` 는 쓰지 않는다** — `{학생 아이디}p` 가
  학부모 자리이기 때문이다
- **학부모 아이디는 `{학생 아이디}p`** 이고 최초로 연결된 자녀를 따른다.
  동생이 등록해도 바뀌지 않는다
- **학부모 ↔ 학생은 1:N**

**고려사항**

- **고치는 방법**은 두 번째로 생긴 학생을 지우고 첫 번째의 오타를 고치는 것이다.
  첫 번째에 이미 기록이 붙어 있을 수 있다

#### 같은 사람인지 판정하는 법

**같은 엑셀이 여러 번 들어온다.** 학생이 2주차·3주차에도 들어오므로 같은 반에 파일이
여러 번 올라온다. **업로드는 멱등이어야 한다** — 같은 파일을 두 번 올려서 계정이 두 벌
생기거나 청구가 두 번 나가면 안 된다.

```
셋 다 일치(이름·학생번호·학부모번호)  →  같은 사람. 아무것도 안 한다
번호가 하나라도 일치                   →  묻는다
번호가 하나도 안 맞음                  →  새 학생
```

**이름은 판정에 쓰지 않는다.** 이름만 같은 것은 동명이인이라 물어봐야 소용이 없고,
같은 반에서 계속 걸린다. 이름이 틀렸어도 번호가 맞으면 걸리므로 오타는 그대로 잡힌다.

| 상황 | 번호 일치 | |
|---|---|---|
| 재업로드 | 둘 다 | 셋 다 같으니 **통과** |
| 학생번호 오타 | 학부모번호 | **묻는다** |
| 이름 오타 | 둘 다 | **묻는다** |
| 학부모번호 오타 | 학생번호 | **묻는다** |
| 형제 | 학부모번호 | **묻는다** — 형제일 수도, 남의 번호를 잘못 적었을 수도 |
| 동명이인 | 없음 | **안 묻는다** |

**형제가 맞으면 먼저 만들어진 학부모 계정에 붙인다** — 새 학부모 계정을 만들지 않는다.

**대조키는 쓰지 않는다.** 그건 뒷4자리만 보는 지면 대조용이고, 계정 판정은 전체 번호로 본다.

**학년·학교는 저장만 하고 판정에 쓰지 않는다.** 같은 반이면 대부분 겹쳐서 신호가 되지 않는다.

### 2-4. 발송

```
① 명단 붙여넣기      열 지정 · 학교 별칭 · 중복 확인 · 학부모 확인
   │  ← 이 구간은 확정되지 않는다. 나갔다 들어왔다 할 수 있다
   ▼
② 무엇을 청구할까     교재 목록에서 고른다
                     컨펌
                     스킵 확인          ← 청구가 안 나갈 학생
   │
   ▼
③ 계정 생성          결제선생 + 아이디 문자가 **함께** 나간다   ← 배치 완료
```

**청구를 고르는 것이 두 번째 화면이다.** 명단을 맞추는 일과 무엇을 청구할지 정하는
일이 섞이면 둘 다 어려워진다.

**스킵은 시스템이 고른다.** 조교가 한 명씩 빼는 것이 아니다.

```
같은 교재로 이미 청구가 나간 학생   →  스킵
결제선생을 안 쓰는 반(2-7)         →  반째로 스킵
```

같은 명단이 2주차·3주차에도 들어오므로(2-3) 이 판정이 없으면 **재업로드가 청구를
두 번 낸다.** 계정 안내는 이미 있는 학생에게 안 나가지만 **청구는 다르다** —
수업마다 새로 사는 것이라 "계정이 있다" 로는 못 가른다.

그 전까지는 아무것도 만들어지지 않는다. 아이디와 비밀번호는 임시로 들고 있을 뿐이고
PK 가 할당되지 않는다 — 학생 관리 화면에도 나타나지 않는다.
**문자가 나가야 실제 계정이 된다.**

#### 결제선생

**자동으로 나가지 않는다** — 보낼지 말지 정한다.

```
보낸다  →  ① 무엇을 청구할지 고른다   그 커리의 교재 중 · 전체/학생별
           ② 결제선생 문자           → 학부모에게만
           ③ 알림톡                  왜 청구했는지 · 결제선생으로 간다는 안내
```

**알림톡이 따로 나가는 이유**는 결제선생 문자만 받으면 무엇에 대한 청구인지 모르기
때문이다.

**형제는 묶지 않는다.** 아이디마다 따로 청구가 나간다. 대신 **문자에 누구 것인지
이름을 적는다** — 학부모가 두 건을 받으면 어느 아이 것인지 알아야 한다.

#### 계정 안내 — 같은 시점에 나간다

순서대로 나가는 것이 아니라 같이 나간다.

- **학부모에게 자녀가 둘이면 묶어서** 한 번에
- **비밀번호는 임시로** 만들고 LMS 에 들어가기 전에 반드시 바꾸게 한다 — 둘 다

  ```
  랜덤 8자리 · 0 · 1 · o · l 을 뺀다
  ```

  **헷갈리는 글자를 빼는 이유**는 알림톡으로 받아서 눈으로 보고 타이핑하기
  때문이다. `0`/`O`, `1`/`l` 이 섞이면 로그인이 안 되는데 왜 안 되는지 알 수 없다

- **비밀번호를 잊으면 Teacher 가 되돌린다** → 새 랜덤을 발급하고 다시 변경을
  강제한다. 학생·학부모가 스스로 복구하는 길은 두지 않는다 — 사람이 처리한다

**학생 전화번호가 없으면 학부모가 대신 받는다** — 학생 계정 정보까지 학부모 번호로
나간다. 엑셀에 학생 번호와 학부모 번호가 같게 오면 학부모 번호로 본다.

**이미 계정이 있으면 안내가 안 나간다**(학생·학부모 모두). 결제는 나간다 — 계정은
한 번 만들면 끝이지만 교재는 수업마다 새로 사기 때문이다.

| 이 사람이 | 계정 안내 | 결제 |
|---|---|---|
| 처음 온다 | 나간다 | 나간다 |
| 계정이 있다 | **안 나간다** | **나간다** |
| 계정이 있는데 다른 반이다 | **안 나간다** | **나간다** — 수강만 추가되고, 커리가 달라도 똑같다 |

---

### 2-5. 그 뒤 — 학생·결제 관리

#### 무엇을 샀는지 학생이 들고 있다

결제가 확인되면 그 학생이 어느 교재를 샀는지 목록으로 남는다.
반별 학생 관리 화면과 학생 상세 화면에서 보고 고친다.

**일괄 적용이 된다** — "이 반 전원이 이 교재를 샀다" 를 한 번에 찍는다. 결제가 우리
밖에서 이뤄지는 경우가 있기 때문이다(2-7).

#### 개별 발송 — 언제든 다시 보낼 수 있다

| 보낼 것 | |
|---|---|
| **아이디 안내** | **학부모·학생을 따로** 고른다 |
| **결제 요청** | 개별로 |

언제든 가능해야 한다. 문자를 못 받았다거나 번호를 고쳤다거나 하는 일이 계속 생긴다.

#### 결제 건은 개별로 다룬다

- 결제 내용이 **행으로** 보인다. 취소·환불된 건도 같은 행으로 남는다
- 건별로 **취소 · 환불**

**부분 환불은 전액 취소 + 재결제다.** 결제선생이 전액 취소만 지원한다. 학부모에게는
취소 안내와 새 청구가 각각 나간다.

**결제 관리는 반 밖에서도 한다** — 반과 무관하게 전체를 필터로 훑는 화면이 있다.
영상과 같은 결이다(1-7).

#### 발송 내역이 학생마다 남는다

**알림톡·결제선생 발송 내역**이 학생별로 계속 보여야 하고, 어느 번호로 나갔는지도
남아야 한다. "안 받았다" 는 말이 계속 나오는데, 기록이 없으면 다시 보내는 것 말고
할 수 있는 일이 없고, 그러면 같은 문자가 두 번 가거나 정작 필요한 사람은 계속 못 받는다.

### 2-6. 학생 상세 페이지

2-3 에서 "수정" 을 고르면 오는 곳이고, 학생에 대한 것이 여기 모여 있다.

| | |
|---|---|
| 학교 | |
| **학년** | 아래 승급 규칙 |
| **학생 번호** | 고칠 수 있다 → 아이디가 바뀐다 |
| **학부모 번호** | 고칠 수 있다 → 아이디가 바뀌고 청구도 다시 나간다 |
| 대조키 | 파생값 |
| 구입한 교재 | 2-5 |
| 발송 내역 | 2-5 |

여기서 전부 고칠 수 있다.

#### 학년은 다섯 뿐이고, 2월 마지막 날에 오른다

```
예비 고1  →  고1  →  고2  →  고3  →  N수  →  N수 (멈춤)
```

- 다섯 말고는 없다. 중3·중2 같은 것은 두지 않고 전부 `예비 고1` 로 통칭한다
- **2월 마지막 날에 자동으로 오른다** — 3월 새 학년이 시작되기 직전이다
- **N수는 더 오르지 않는다**

#### 번호를 고치면 아이디가 바뀐다

아이디가 뒷4자리에서 나오기 때문이다(2-3).

| 틀린 것 | 하는 일 |
|---|---|
| 학생 번호 | 아이디·비밀번호 재생성 → **학생 계정 안내 재발송** |
| 학부모 번호 | 아이디·비밀번호 재생성 → 안내 재발송 **+ 결제선생 청구 재발송** |

학부모 번호가 틀리면 **청구서가 엉뚱한 번호로 갔다는 뜻**이라 청구도 다시 나가야 한다.

**대조키도 같이 바뀐다.** 다만 이미 낸 답안지는 그대로 둔다 — 대조는 낼 때 한 번 끝난
일이고, 소급해 다시 돌리면 조교가 손으로 고른 것까지 뒤집힌다.

**학생 정보(수강 이력·출결·성적)는 그대로 둔다.** 계정을 다시 만드는 것이 아니라
아이디와 비밀번호만 다시 만든다.

**고려사항**

- **대조키가 같은 학생이 한 반에 둘이면 자동으로 못 가른다.** 지면에서 오는 것은
  이름과 뒷4자리가 전부라 구분할 근거가 없다. **매번 사람이 지정한다** —
  조교가 고른 것을 기억해 재사용하는 방식은 검토했다가 버렸다(맞는 경우가 없고,
  겹칠 때 두 번째 학생의 답안지가 첫 번째에게 조용히 붙는다)

### 2-7. 장소마다 결제 방식이 다르다

| 장소 | 교재값을 누가 받나 |
|---|---|
| **미래탐구** | 결제선생 |
| **러셀** | **학원이 따로 받는다** — 결제선생이 나가면 안 된다 |

둘 다 정해진 기간 전에 계정은 만들어 준다. 차이는 결제뿐이다.

**장소로 자동 판정하지 않는다. 반 단위로 조교가 고른다.** 고르는 자리는 이미
있다(2-4). 러셀은 결제가 우리 밖에서 끝나므로 **교재를 샀다는 표시를 일괄로**
찍어야 한다(2-5).

## 3. 수업

수업이 도는 동안. 주차 하나 안에 출결표와 OMR 이 같이 있고, OMR 이 출결을 만든다.

```
① 반별 관리 열기     누가 무엇을 결제했나 → 교재 배분
② 시험 만들기        문항 · 정답 · 배점을 넣고 **그 반 그 주차 회차에 묶는다**
③ 모의고사 채점      OMR → 대조 → 조교 보정 → 성적표 · 반 평균
④ 출결               대조된 학생은 자동으로 출석
⑤ 출결 확정          누르면 영상이 나가고 통지가 나간다

반이 끝나면 닫는다(3-10) — 매주 하는 일이 아니다.
```

---

### 3-1. 반별 관리 페이지

조교가 연다. 반을 열면 **격자**가 있다 — 가로가 주차, 세로가 학생이다.

```
              1주차   2주차   3주차   4주차 …
  김하늘       출석    결석    출석
  이서준       출석    출석    동보
  박지우        x      x      출석     ← 3주차에 들어왔다
```

**주차를 열면 세로 한 줄**이다 — 그 주 전원의 출결표·OMR·워크북(3-2).
**학생을 열면 가로 한 줄**이다 — 그 학생이 이 반에서 어땠는가.
조교가 수업 끝나고 하는 일은 세로고, 학부모 전화가 오면 보는 것은 가로다.

**그때 이 반에 없던 학생은 `x`** 다. `미입력`(3-4)과도 갈라 놓는다 — 미입력은
"아직 안 봤다" 이고 `x` 는 "볼 것이 없다" 이다. 3주차에 들어온 학생의 1·2주차를
미입력으로 두면 조교가 영원히 채워야 할 칸으로 남는다.

여기서 누가 무엇을 결제했는지도 본다. 그에 따라 교재를 배분한다 —
**미래탐구에서만** 한다(러셀은 학원이 따로 받으므로 2-7).

---

### 3-2. 주차 하나 = 출결표 + OMR + 워크북

**주차는 닫히지 않는다.** 매주 누르는 것은 `출결 확정`(3-11)이고 그것도 잠그지
않는다 — 확정 뒤에도 출결은 계속 바뀐다. 반을 끝내는 것은 따로다(3-10).

```
3주차
  ├ 출결표
  ├ OMR        ← 고치면 출결표가 따라온다
  └ 워크북
```

**OMR → 출결표는 흐르고, 반대는 없다.** 출결을 손으로 고쳐도 OMR 은 건드리지 않는다.

**셋은 각각 따로 본다.** 데이터가 흐를 뿐 화면이 겹치지 않는다.

```
출결표 한 줄    이름 · 원번 · 대조키 · 학교 · 학년 · 출결
```

**출결표에 OMR 대조 상태나 워크북 제출 여부를 넣지 않는다.** 그것들은 반 격자(3-1)
에서 모아 본다.

#### 수행도

**`A`·`B`·`C`** 세 등급이고 **값으로 담는다.** 학생·학부모 화면에 등급이 뜨고,
사진도 같이 본다.

### 3-3. 모의고사 채점 — OMR

**OMR 은 한 반 것이 한 번에 다 들어온다.** 오늘 열 장, 내일 열 장으로 나눠 들어오지
않는다. 그래서 반쯤 채점된 중간 상태가 없다.

#### 대조는 세 단계로 좁힌다

```
① 대조키           {이름}{뒷4자리} 로 찾는다
② 반 안에서        이름·전화 중 하나가 비면 이 반의 명단으로 찾는다
                      → 찾아도 "매핑 불확실" 로 표시한다
③ 조교             그래도 못 찾으면 사람이 고른다
```

②로 찾은 것은 확실하지 않다. 반 안에서 좁혔을 뿐이라 틀릴 수 있고, 틀리면 다른 학생의
성적에 붙는다.

#### 확실하지 않은 것은 위로 올린다

| 무엇이 불확실한가 | |
|---|---|
| **마킹** | `x` 로 표시한 것 · 체크로 표시한 것 · 희미한 것 |
| **이름·전화** | 읽히지 않았거나 빈칸 |
| **매핑** | 위 ②로 찾은 것 |

#### 성적표와 반 평균은 그래도 나온다

정보가 덜 찼어도 성적표는 만들고, 이 모의고사의 반 평균을 낸다.

#### 아무에게도 안 붙는 장은 안 붙은 채로 둔다

명단에 없는 이름이 나왔는데 다른 반 학생도 아니면 **새 학생**이다. 계정도 청구도
아직 없으므로 그 자리에서 만들 수 없다.

```
답안지가 안 붙은 채로 남는다   ← 지우지 않는다. 성적은 이미 나와 있다
   ↓
수업 날 학생관리기록카드를 받는다   ← 지면. 오프라인
   ↓
계정 발급으로 간다(2-4)          ← 여기서 청구할지 정하고 문자가 나간다
   ↓
OMR 로 돌아가 그 장을 학생에 붙인다
```

**계정은 언제나 계정 발급을 거친다.** OMR 이나 워크북에서 학생을 그 자리에서
만들지 않는다 — 거기서 만들면 **청구를 정할 자리도, 문자가 나갈 자리도 없다.**
2-4 의 *"문자가 나가야 실제 계정이 된다"* 가 여기서도 그대로다.

**성적표가 계정보다 먼저 나온다.** 학생을 만들기 전에 이미 채점이 끝나 있고,
붙이는 것은 나중에 사람이 한다.

**워크북도 같다.** 지면의 이름·번호가 아무에게도 안 붙으면 같은 길로 간다.

**고려사항**

- **OMR 은 다시 돌리면 덮어쓴다.** 그전 행을 다 지우고 새로 만들며 성적도 다시 쓴다.
  **다만 사람이 한 것은 살아남는다** — 조교가 고른 매핑, 안 붙은 장을 학생에 붙인 것,
  손으로 찍은 출결은 그대로다(3-4)
- **잘못 붙였으면 다시 붙인다.** 매핑은 몇 번이든 고칠 수 있고, 고치면 그 장에서 나온
  출결·성적이 옛 학생에서 걷힌다. **다만 이미 나간 문자는 못 되돌린다** —
  틀린 성적표 링크를 받은 학부모가 있으면 그건 전화로 푼다
- **OMR 용지는 우리가 만든다.** 남의 서식을 읽는 것이 아니라 지금 샘플을 바탕으로
  우리 서식을 찍어 쓴다. 그래서 25문제·마킹란·읽는 방식이 전부 우리 손에 있다

  | | |
  |---|---|
  | 평가원 모의고사 설문조사 | **OMR 로 읽되 이름·번호를 안 적으면 학생에 안 붙는다** — 조교가 집계만 본다("6월 평균은 이랬다"). 이름·번호를 적었으면 학생에 붙는다 |
  | 설문조사의 전화번호가 5자리 | 그 자리는 **수험번호**다. 지금 설계는 전화 4자리 전제 |

### 3-4. 출결 상태

| 상태 | 어떻게 되나 |
|---|---|
| **미입력** | **기본값이다.** 조교가 아무것도 안 눌렀거나 눌렀던 것을 해제하면 여기 남는다 |
| **결석** | 조교가 **직접 찍은 것**이다. 안 찍힌 것과 갈린다 |
| **출석** | OMR 이 대조되면 자동으로 바뀐다 — **조교가 이미 찍은 값은 안 덮는다**. **시험을 안 보는 학생도 있으므로** 손으로도 바꾼다 |
| **퇴원** | 조교가 직접 처리한다. **로그인이 막힌다**(아래) |
| **동보** | 결석분의 **그 주 보강 영상**을 신청하면 자동으로 바뀐다 |
| **결석(현보)** | 결석했지만 **다른 반에 가서** 그 주 수업을 들었다 |

**`현보` 는 값이 아니라 배지다.** 방문한 반 출결표에서는 그 학생이 `출석` 이고,
옆에 원래 반이 배지로 붙는다(3-4 아래). 값으로 남는 것은 **원래 반의
`결석(현보)`** 하나다 — 여기를 `결석` 으로 적으면 보강을 끝낸 학생 집에
결석 전화가 걸린다.

**원래 반이 어디인지는 따로 저장하지 않는다.** 그 학생의 수강이 곧 답이다 —
방문한 반 출결표는 명단을 넓혀 그 학생을 넣지만, 반 이름은 수강에서 읽으므로
자동으로 원래 반이 뜬다.

**`미입력` 에서는 아무것도 나가지 않는다.** 결석 문자도, 동보도, 결석생 연락 목록도
`결석` 을 찍어야 걸린다. 안 찍은 것과 없었던 것을 시스템이 구별 못 하면 조교가
아직 안 본 학생의 학부모에게 결석 문자가 나간다.

#### 퇴원하면 로그인이 막힌다

**계정과 데이터는 그대로 둔다.** 지우지 않는다 — 지난 출결·성적·워크북이 다 붙어 있고,
반 평균도 그때 그 학생을 세고 끝난 이야기다. 막는 것은 **들어오는 것 하나**다.

| | |
|---|---|
| **그 반** | 명단에서 빠진다. 지난 기록은 남는다 |
| **학생** | **듣던 반이 그 하나뿐이면** 로그인이 막힌다. 여러 반이면 **그 반만** 빠지고 로그인은 된다 |
| **학부모** | **자녀가 전부 나갔을 때만** 같이 막힌다. 남은 자녀가 있으면 드롭다운으로 본다(4-2) |

**퇴원은 수강 단위다.** 수능 반만 그만둔 학생이 내신 반까지 잠기면 안 된다.
막는 것은 **남은 수강이 하나도 없을 때**다.

**저장하는 그 순간 막힌다.** 나중에 도는 작업이 아니다.
그리고 **로그인 화면이 왜 안 되는지 말해 준다** — 아이디·비밀번호가 틀렸다고 하면
학생이 계속 다시 쳐 보고 조교에게 전화한다.

---

#### 동보

```
신청  +  결석 확인   →  자동 지급  →  일주일 뒤 회수
```

결석한 그 주차의 영상을 받는다.

**둘이 다 있어야 나간다.** 순서는 상관없다 — 5주차 결석을 미리 신청해 두면 출결표
`출결 확정` 으로 결석이 확정될 때 나가고, 이미 확정된 뒤에 신청하면 그때 바로 나간다.

**`결석(동보)` 는 결석이다. 다만 결석생 연락 목록에서는 빠진다**(3-12). 그 목록은
"결석했다" 가 아니라 **"보강이 아직 정해지지 않았다"** 를 담기 때문이다 — 영상을
받아 갔으면 물어볼 것이 없다. `결석(현보)` 도 같다.

**`동보` 는 우리끼리 쓰는 말이다.** 학생·학부모에게 나가는 어떤 문구에도 안 쓴다 —
화면에도, 문자에도, 전화에도. 그쪽에 쓰는 말은 이렇다.

```
오늘 수업에 결석했습니다
LMS 에서 결석생 영상을 신청할 수 있습니다
```

결석이 확정되면 **강의 영상 탭에서 그 주차의 신청이 열린다.** 따로 알리지 않는다 —
문자는 결석한 집에 안 가고(3-11), 학생이 영상을 보러 들어오면 거기 있다.

**지난 주차만 신청할 수 있다.** 4주차에 있으면 3주차·2주차를 신청할 수 있지만,
3주차에 있으면 4주차는 못 한다 — 아직 하지 않은 수업이다.

**영상은 자동으로 나가므로 문자가 없다.** 문자가 나가는 것은 클리닉뿐이다(3-11) —
클리닉은 승인을 거치고 자리와 시간이 잡히므로 결과를 알려야 온다.

- **학생과 학부모 둘 다** 신청할 수 있다 — 동보만 그렇다(클리닉은 학생만)
- **승인이 없다.** 결석했다는 근거가 이미 출결에 있으므로 사람이 한 번 더 볼 것이 없다
- **이미 그 영상을 가진 학생에게는 안 나간다**(3-5)

> **지금 시스템과 다르다.** 지금은 동보도 승인을 거치게 돼 있다.
> 이 문서가 기준이므로 그 단계를 걷어내야 한다(부록).

#### 현보

**조교가 지정한다.** 학생이 신청하는 것이 아니다. 두 갈래로 생긴다.

```
시험을 봤다   OMR 이 들어왔는데 이 반 명단에 없다
              → 조교가 판단한다: 새 학생인가, 다른 반 학생이 온 것인가
              → 다른 반이면 현보로 찍는다

시험을 안 봤다  조교가 출결표에 직접 더한다
```

**첫 번째가 흔하다.** OMR 대조가 실패하는 이유 중 하나가 현보이기 때문이다 —
명단에 없는 이름이 나오면 새 학생일 수도 있고 남의 반 학생일 수도 있어서
조교가 갈라 준다(3-3).

현보로 받는 순간부터 그 한 주 동안 이 반의 학생이 된다.

**출결 레코드는 두 반에 다 생긴다.** 값이 반대편끼리 다르다.

| | 그 주 값 | 왜 |
|---|---|---|
| **방문한 반**(목반) 출결표 | `출석` | 실제로 여기 와서 수업을 들었다. 옆에 원래 반을 배지로 붙인다 |
| **원래 반**(화반) 출결표 | `결석(현보)` | 화반 수업에는 안 왔다. 다만 보강을 마쳤으므로 결석과 갈라 놓는다 |

**`결석(현보)` 를 그냥 `결석` 으로 적으면 안 된다.** 결석생 연락 목록이 그 값으로
갈리므로, 보강을 이미 끝낸 학생의 학부모에게 전화가 걸린다(3-12).

행이 둘이어도 **영상도 문자도 한 번만 나가고 반 평균에도 한 번만 센다.**
문자는 **보강을 간 반**에서 나간다 — 그 주에 실제로 수업을 들은 곳이고, 성적표도
거기서 나온다. 원래 반은 `결석(현보)` 라 문자가 안 나간다(3-11). 영상은 학생과 영상을
짝지어 보므로 먼저 확정한 쪽에서만 나가고 만료도 안 밀린다(3-5). 평균은 출결이 아니라
성적에서 세는데 성적은 시험당 학생당 한 줄이다.

| | |
|---|---|
| 영상 | 이 시점부터 나가고 **일주일 뒤 회수** |
| 클리닉 | 다른 학생과 같다 — 기준점은 **그 시험 전체 평균**(3-7) |
| 클리닉 신청 | **그 슬롯 전날까지** — 다른 학생과 같은 규칙이다 |

**원래 반이 어디인지는 규칙에 쓰지 않는다.** 클리닉 슬롯마다 자기 날짜가 있고 신청은 그
전날까지다 — 현보든 아니든 같다.

#### 출결표에 원래 반이 보여야 한다

규칙에는 안 쓰지만 화면에는 보여야 한다.

```
출결표 · 목 6.5 대치러셀 · 3주차
  김하늘        출석
  이서준        출석
  박지우  현보  출석    ← 원래 화 6.5 대치러셀
```

조교가 그 자리에서 왜 이 학생이 여기 있는지 알아야 하기 때문이다. 명단에 없던
이름이 갑자기 있으면 잘못 들어온 것으로 보인다.

점수는 이 반 평균에 넣는다. 시험을 봤으면 다른 학생과 똑같이 센다.

### 3-5. 영상 지급

**조교가 `출결 확정` 을 누르면 출석한 학생에게 나간다.**

**출결표 자체는 계속 살아 있다.** OMR 을 다시 돌리거나 안 붙었던 답안지를 학생에
붙이면 그때마다 출결이 따라 바뀐다 — 저장을 누르는 것이 아니다. `출결 확정` 은
*"이제 내보낸다"* 는 뜻이고, 그래서 이름이 저장이 아니다.

**다시 눌러도 아직 못 받은 학생에게만 나간다.** 확정 뒤에 출결이 바뀐 학생이
여기서 채워진다.

**같은 영상을 두 번 주지 않는다.** 이미 가진 학생은 건너뛰고, 만료는 처음 준 시점
+ 일주일 그대로다. 출석으로 받은 영상을 클리닉이나 현보로 또 받게 되는 자리가 있다.

### 3-6. 수업 중에 교재가 늘어날 수 있다

4주차·5주차에 자사 모의고사 같은 것을 새로 팔 수 있다. 조교가 미는 것이 아니라
**학생이 LMS 에서 직접 신청**한다.

```
학생이 신청  →  결제선생이 나간다  →  결제 완료  →  "구입한 교재" 에 뜬다
```

§2 의 등록 배치와 다른 점은 학생이 시작한다는 것뿐이다.
**표지 사진이 여기서 쓰인다**(1-6).

---

### 3-7. 클리닉과 영상

| | |
|---|---|
| **클리닉 대상** | 출석 + 시험 응시 + **평균 미달**. 기준점은 관리자 컷, 없으면 **그 시험 전체 평균** |
| **클리닉 신청** | **학생만.** 학부모는 못 한다. **승인을 거친다** — 동보와 반대다 |
| **클리닉 마감** | **그 슬롯 전날까지.** 월요일 수업의 금요일 클리닉이면 목요일이 마감이다. 현보도 같다. **당일 취소는 노쇼로 센다** |
| **클리닉 시점** | 잡을 수 있는 슬롯은 **그 주 금요일**까지다 — 다음 수업 전이라는 뜻이고, 월요일 수업이면 금요일이 마지막이다 |
| **클리닉 정지** | **노쇼 2회면 못 한다** — 잡아 놓고 안 오면 그 자리를 다른 학생이 못 쓴다. **학생 상세에서 푼다**(2-6) |
| **영상 부여·회수** | **`출결 확정` 을 누를 때** 부여, 부여 + 일주일에 회수(3-5) |

**동보는 자동, 클리닉은 승인**이다. 동보는 결석이라는 사실이 이미 확정돼 있어 더 볼 것이
없지만, 클리닉은 자리와 시간을 잡는 일이라 조교가 배정해야 한다.

#### 슬롯 — 커리가 시간대를 갖는다

**슬롯은 월요일부터 금요일까지 선다.** 주말은 없다.
**커리를 만들 때 시간대를 정한다**(1-2). 한 시간 단위로 쪼개지고,
**범위 끝은 마지막 타임이 끝나는 시각**이다.

```
3–9시   →   3 · 4 · 5 · 6 · 7 · 8시 시작    6타임
6–8시   →   6 · 7시 시작                    2타임
```

**언제든 고칠 수 있다. 고친 날 이후부터만 적용된다** — 지나간 날의 슬롯과 이미
잡힌 신청은 그대로 둔다. 옛 설정으로 잡힌 것을 소급해 옮기면 학생이 온다고 한
시간이 말없이 바뀐다.

#### 정원은 클리닉 조교 수다

**한 타임에 조교 수만큼 받는다.** 조교가 둘이면 두 명, 하나면 한 명이다.
클리닉 화면에서 보고 고친다.

**이것도 과거는 안 건드린다.** 조교를 하나로 줄여도 이미 두 명이 잡아 둔 지난
슬롯은 그대로다.

> **지금 시스템과 다르다.** 코드는 정원이 **`1` 로 못 박혀** 있다 —
> 기본값·`editable=False`·`CheckConstraint` 셋이 같이 걸려 있고, 잔여석을 안
> 보여 주는 것도 거기서 나왔다(2026-07-21 회의 *"시간별로 학생 한 명씩"*).
> 이 문서가 기준이므로 그 셋을 걷어내야 한다(부록).

#### 신청이 어떻게 끝나나

```
대기       학생이 신청했다
  ├ 승인배정   조교가 슬롯을 배정했다  →  문자
  ├ 미승인     조교가 반려했다        →  문자. 사유와 함께
  └ 취소       학생이 물렀다
```

**반려 사유는 고르는 것이다.** 조교가 문장을 쓰지 않는다 — 값에서 고르면 그 사유가
문자에 실리고, **다른 시간에 다시 신청하라**는 말이 같이 나간다. 안 알리면 학생은
왜 안 잡혔는지 모른 채 기다린다.

#### 그날

```
5분 전    문자. 클리닉 페이지 링크가 실린다 — 로그인하면 그 화면으로 간다
   ↓
정각
   ↓
5분 후    아직 안 왔으면 문자 — "오늘 예정된 클리닉에 참석하지 않고 계십니다"
   ↓
10분 후   조교가 노쇼로 찍는다
```

**노쇼는 사람이 찍는다.** 시계가 자동으로 찍지 않는다 — 늦게라도 오는 학생이 있고,
자리에 앉은 뒤에 기계가 결석으로 남기면 되돌릴 사람이 없다.

배정된 뒤의 결과는 **미처리 · 출석 · 결석**이고 `결석` 이 노쇼다.

**당일 취소는 노쇼와 같다.** 자리는 이미 비워 둘 수 없는 시점이고, 전날까지 무르는
것과 같이 셀 수 없다(클리닉 마감이 그 슬롯 전날인 것과 같은 이유다).

**노쇼가 둘이면 신청이 막히고, 정지는 학생 상세에서 푼다**(2-6).
영구 정지가 아니다 — 사람이 판단해서 연다.

---

### 3-8. 새 학생은 계속 생긴다

3-3 에서처럼 **수업 중에도 학생이 늘어난다.**

- **언제든 아이디 안내·결제선생을 보낼 수 있다**(2-5 의 개별 발송과 같다)
- 한 번도 안 보낸 학생은 일괄로도 보낸다
- 정보를 고친 뒤 다시 보낼 수 있다
- **어느 번호로 나갔는지**가 발송 내역에 남아야 한다

---

### 3-9. 반 이동

조교가 학생의 반을 옮길 수 있다.

- **같은 커리 안에서만 옮긴다.** 커리가 다르면 교재가 다르고(1-6) 이미 낸 돈을
  어떻게 할지가 따라오는데, 그건 옮기는 일이 아니라 새로 등록하는 일이다
- **옮기는 즉시 그 반의 룰**을 적용받는다
- **지난 기록은 옛 반에 남는다.** 출결·성적은 그 반의 회차에 달려 있고 회차는 안
  움직인다 — "즉시" 가 지난 수업까지 소급한다는 뜻은 아니다. 옛 반 출결표에서
  그 줄이 사라지지 않도록 명단이 **그 회차에 기록이 있는 학생도** 포함한다
- 이미 나간 영상은 그대로 간다 — 회수는 지급 시점 + 일주일이라 반과 무관하다
- 이미 잡힌 클리닉도 그대로다 — 슬롯에 붙은 것이라 반이 바뀌어도 움직이지 않는다

### 3-10. 수업 닫기

| | |
|---|---|
| 드롭다운·새 등록 | **사라진다** |
| 과거 기록(출결·성적·영상 권한·결제) | **그대로 조회된다** |

지난 기록이 그 반을 참조하고 있다. 지우면 "어느 반의 3주차 결석" 이었는지를 알 수 없게 된다.
교재의 `Active` 와 같은 방식이고, 지금 시스템도 이미 그렇게 하고 있다(부록).

### 3-11. 알림톡이 나가는 시점

지금까지의 흐름에서 **반드시 나가야 하는 것만** 추린 여덟이다.

| # | 언제 | 누구에게 | 왜 |
|---|---|---|---|
| 1 | **계정 발급**(2-4) | 학생 · 학부모 | 아이디·임시 비밀번호를 모르면 못 들어온다. 자녀가 둘이면 학부모에게 묶어서 |
| 2 | **교재 청구**(2-4) | 학부모 | 결제선생 문자만 받으면 **무엇에 대한 청구인지 모른다** |
| 3 | **결제 취소·환불**(2-5) | 학부모 | **업체가 알리지 않는다.** 우리가 안 보내면 아무도 모른다 |
| 4 | **출결 통지**(아래) | 학생 · 학부모 | 그 주에 있었던 일을 한 번에 전한다 |
| 5 | **클리닉 확정**(3-7) | 학생 · 학부모 | 승인제라 결과를 알려야 온다 (신청은 학생만 하지만 결과는 둘 다 본다) |
| 6 | **클리닉 반려**(3-7) | 학생 | 안 알리면 왜 안 잡혔는지 모른 채 기다린다 |
| 7 | **클리닉 5분 전**(3-7) | 학생 | 잊고 안 오는 것을 막는다. 클리닉 페이지 링크가 실린다 |
| 8 | **클리닉 5분 후 미참석**(3-7) | 학생 | 아직 안 온 학생을 부른다. 10분 후 조교가 노쇼로 찍는다 |

**신청했을 때는 안 보낸다** — 학생이 직접 한 일이라 이미 안다. 보내는 것은 확정부터다.

**어느 포맷으로 나갈지는 반이 갖는다** — 반을 만들 때 드롭다운으로 고른다(1-2).
이 구조는 나중에 바뀔 수 있다.

**개별 재발송**(2-5)은 1·2 를 다시 보내는 것이라 새 시점이 아니다.

#### 나가는 곳은 둘이다

**문자로 나가고, 앱 안에도 쌓인다.** 앱이 아니라 웹이지만 알림은 뜬다.

```
문자        받는 사람 손전화로
앱 안 알림   로그인하면 목록에 쌓여 있다 — 안 읽은 것이 표시된다
```

같은 사건이 두 곳에 간다. 문자를 못 봤어도 들어오면 남아 있다.

| | |
|---|---|
| **읽음** | 열면 읽힌다 |
| **모두 읽음** | 한 번에 |
| **목록** | 스무 개까지 보이고 그 뒤는 스크롤 |

#### 조교는 무엇이든 다시 보낼 수 있다

**여덟 중 어느 것이든** 조교가 다시 보낸다. 못 받았다는 연락이 오거나, 번호를 고쳤거나,
그냥 한 번 더 필요할 때다.

**어디서든 보낸다** — 그 수업 화면에서도, 학생 상세에서도, 발송 내역에서도.
한 자리에서만 되면 조교가 그 자리를 찾아 헤맨다.

#### 4 — 출결 통지

**조교가 `출결 확정` 을 누르면 나간다.** 영상 지급과 같은 동작이다(3-5).

```
수업 당일   수업 · OMR 수거 · 워크북 수거
   ↓
조교        OMR 채점 → 안 붙은 장 처리 → [출결 확정]
   ↓
            영상이 나가고 통지가 나간다
```

**그 반 전체에 한 번에 나간다.** 한 명씩 고르는 것이 아니다.
**다만 결석은 뺀다**(2026-08-19). 결석한 집에는 다음날 조교가 전화를 걸기 때문에
(3-12) 문자가 먼저 가면 같은 이야기를 두 번 하는 셈이 된다.

**문자는 처음 확정할 때만 나간다.** 그 뒤로 몇 번을 눌러도 영상만 채워지고
문자는 안 나간다 — 오타 하나 고칠 때마다 문자가 가면 안 되기 때문이다.
**날짜로 판정하지 않는다.** 누른 그 시점이 곧 부여 시점이다.

**확정해도 출결표는 계속 바뀐다.** 확정은 *"이제 내보낸다"* 는 뜻이지
*"더 못 고친다"* 는 뜻이 아니다.

#### 확정이 여는 것

확정하면 그 주에 대해 나갈 수 있는 것이 열린다.

```
영상 발송 · 문자 발송 · 성적표
```

#### 그 뒤에는 수동으로 보낸다

출결표는 계속 고칠 수 있다. **다만 그 뒤로는 문자가 자동으로 나가지 않는다.**

대신 **화면이 표시해 준다** — 누구에게 무엇이 안 나갔는지, 누가 바뀌었는지.

```
3주차 · 목 6.5 대치러셀            [확정됨]
  김하늘   출석                     ✓ 발송
  이서준   결석 → 출석  (수정됨)     ⚠ 재발송 필요   [보내기]
  박지우   출석                     ⚠ 미발송        [보내기]
  최유진   결석                     — 해당 없음
```

조교가 버튼을 눌러 보낸다. 오타 하나 고칠 때마다 문자가 나가면 안 되고,
결석↔출석처럼 **학부모가 알아야 하는 변화**만 골라 보내야 하기 때문이다.

**결석은 `— 해당 없음` 이다.** 안 보낸 것이 아니라 **보낼 것이 없는 것**이라
버튼도 없다. `⚠ 미발송` 으로 두면 조교가 채우려고 누르고, 그러면 출결 칸이
`왔다` 하나뿐인 문자가 결석한 집으로 간다.

성적표는 이렇게 나간다.

| | |
|---|---|
| **오프라인** | 지면으로 뽑아 나눠 준다. **반 전체 일괄 프린트와 학생 하나만 프린트가 둘 다 된다** |
| **온라인** | 알림톡에 **링크**로 실린다 — 문자에 성적을 적는 것이 아니다 |

그 링크를 보내면서 그 주에 관한 것을 함께 전한다.

| 담기는 것 | |
|---|---|
| **출결** | 왔다 |
| **성적** | 이번 회차 결과 |
| **워크북** | 냈는지 |
| **클리닉** | 대상이면 "이렇게 신청한다" |

**결석한 집에는 이 문자가 안 간다**(위). 그래서 여기 담기는 것도 온 학생 기준이다 —
"안 왔다" 를 적을 자리가 없고, 동보 안내도 넣지 않는다.

같은 주 이야기를 네 번 나눠 보내면 학부모는 무엇이 새 소식인지 모르고, 정작 봐야 할
것(클리닉 대상)이 묻힌다.

받는 사람에 따라 내용이 갈린다 — 클리닉 대상이 아니면 클리닉 줄이 없다. 카카오
템플릿은 문구가 고정되므로 **이 갈래를 템플릿 몇 개로 표현할지가 `PRD 8-17` 에서
정해져야 한다.**

**링크라서 갈래가 줄어든다.** 점수·과목별 결과처럼 사람마다 다른 것은 링크 너머에
있으므로 템플릿 문구에 안 들어간다. 문자에 남는 것은 출결·클리닉·동보처럼 있고
없고가 갈리는 몇 줄뿐이다.

**링크는 로그인해야 열린다.** 성적은 개인정보이므로 주소만으로는 못 본다. LMS 에
들어가서 보는 것과 같은 화면이고, 문자의 링크는 그리로 데려다줄 뿐이다.

#### 일부러 안 보내는 것

| | 왜 |
|---|---|
| 영상 지급 | 학생이 LMS 에서 바로 본다. 매주 문자가 가면 소음이 된다 |
| 동보 지급 | 학생이 **직접 신청**하고 자동으로 나간다 — 자기가 한 일이다 |
| 결석 안내(별도) | **전화로 한다**(3-12). 출결 통지는 결석한 집에 안 가므로(위) 전화가 유일하다 |

**고려사항**

- **템플릿은 사전 승인제다.** 카카오가 문구를 먼저 심사하므로 문구가 확정돼야
  개발이 시작된다

---

### 3-12. 결석생 연락

**결석이 확정되면 다음날 조교가 전화한다.** 채널톡으로 걸고, 화면의 체크로
결과를 남긴다.

```
결석 확정  →  다음날 목록에 뜬다  →  채널톡으로 건다  →  결과 체크
                                      최대 3회
```

**세 번은 마감이 아니다.** 못 받아도 목록에 남고, 그만 걸지 말지도 안내를 보낼지도
사람이 누른다.

## 4. 학생·학부모가 보는 것

§1~3 은 Teacher 쪽 이야기고, 여기는 **받는 쪽**이 무엇을 보고 무엇을 하는지다.

학부모가 보는 것은 학생도 다 본다. 학생 쪽이 더 넓고, 학부모 쪽은 그 부분집합에
자녀 선택이 붙는다.

**반이 둘이면**(수능 반 + 내신 반, 1-1) 달력은 **합쳐서** 본다 — 두 반 수업일이 한
달력에 같이 찍힌다. 주차·성적·출결은 **반마다 갈린다** — 시험이 반의 회차에 붙기
때문이다. 반을 고르는 자리는 아직 없다(부록).

---

#### 처음 들어올 때

```
문자를 받는다  →  로그인  →  비밀번호를 바꾼다  →  안내사항
```

**비밀번호는 반드시 바꾼다.** 임시 비밀번호가 문자로 나갔으므로 그대로 두면 그
문자를 본 사람은 누구든 들어온다. 바꾸기 전에는 다른 화면으로 못 간다.

**바꾸고 나면 보는 것은 안내사항 정도다.** 아직 수업이 시작되지 않았으면 볼 것이
많지 않고, **예비등록이면 교재 결제 현황만** 보인다.

**잊어버리면 조교가 리셋한다**(2-6). 새 임시 비밀번호가 문자로 다시 나가고,
들어오면 **또 반드시 바꾼다** — 처음과 같은 자리다.

---

### 4-1. 학생 — 보는 것 + 하는 것

| 하는 것 | |
|---|---|
| **결석생 영상 신청** | 결석한 주의 보강 영상. 신청하면 **자동 지급**(3-4) |
| **클리닉 신청** | 대상일 때. **승인을 거친다**(3-7). **학생만 할 수 있다** |
| **교재 신청** | 수업 중에 추가로 파는 것(3-6) |
| **영상 시청** | 권한이 있는 주차의 영상 |

| 보는 것 | |
|---|---|
| **이번 주** | 무엇을 하는 주인지 |
| **출결** | 내 출결 |
| **성적표** | 회차별 + **누적** |
| **워크북** | 낸 것 · 수행도 |

---

### 4-2. 학부모 — 보는 것만

하는 것은 없고, 자녀가 무엇을 하고 있는지 확인하는 쪽이다.
**동보 신청만 학부모도 할 수 있다**(3-4). 그것 하나가 예외이고 **클리닉은 학생만** 신청한다.

| | |
|---|---|
| **이번 주** | 자녀가 무엇을 하는 주인지 |
| **출결** | 왔는지 안 왔는지 |
| **성적표** | 회차별 + **누적** |
| **워크북** | 낸 것 · 수행도 |

자녀가 둘 이상이면 드롭다운으로 고른다(2-3). **한 자녀가 퇴원해도 학부모는 계속
들어온다** — 남은 자녀가 있기 때문이다. 자녀가 그 하나뿐이었으면 같이 막힌다(3-4).

---

### 4-3. 성적 분석

점수만 보여 주면 알 수 있는 것이 적어서, 어디가 약한지까지 나와야 한다.

| 나와야 하는 것 | |
|---|---|
| **단원별 성취** | 대단원·중단원에서 어디가 무너지는지 |
| **누적 추이** | 회차를 거치며 나아지는지 |
| **오답마다 학습가이드** | 그리고 그 가이드가 **영상으로 이어진다** |

재료는 이미 있다. 문항마다 대단원·중단원·테마·오답 학습가이드·가이드 영상이
붙어 있고, 단원별 점수는 그것들로 바로 계산된다.

클리닉·동보와도 이어진다. 약점이 보이면 클리닉에서 무엇을 할지가 정해지고, 가이드
영상도 그 자리에서 연결된다.

**고려사항**

- **만들 수 없는 것은 설계에 넣지 않는다.** 시중 성적표의 절반 이상이 전국 표본을 쓰는데
  (표준점수·백분위·등급·상위 %·지원가능대학), 우리에겐 그 표본이 없고 반 평균으로
  대체되지도 않는다 — 반 30명은 표본이 아니다

---

## 5. 화면

§1~4 는 **무슨 일이 일어나는가**이고, 여기는 **그 일을 어느 화면에서 하는가**다.

---

### 5-1. 층은 둘이다

```
반 레벨     이 반의 주차   →  출결 · OMR · 워크북
            이 반의 학생   →  그 반에서의 이력
            이 반의 교재   →  누가 샀나 · 배부

전체 레벨    오늘 걸 전화
            오늘 배정할 클리닉
            미납 · 발송 내역
            반 만들기 · 계정 발급 · 영상 올리기
```

**같은 일이 두 층에 다 보인다.** 조교가 목요일 저녁에는 반으로 들어가 그 주차를
끝내고, 아침에는 전체에서 오늘 할 일을 훑는다. 어느 쪽이 본체라고 정하지 않는다 —
일하는 때가 다르다.

---

### 5-2. 클리닉은 전체 레벨에만 있다

**반을 가로지르기 때문이다.** 목반 학생과 화반 학생이 같은 슬롯을 놓고 다툰다.
반 안에 넣으면 옆 반이 이미 잡은 자리가 안 보이고, 조교가 같은 시간에 둘을 넣는다.

같은 이유로 **전화도 전체 레벨**이다. 결석은 반마다 나지만 전화는 조교가 하루에
몰아서 건다.

---

### 5-3. 묶는 규칙

**보는 것은 언제나 묶는다.** 걸 집 세 곳, 배정할 신청 열 건, 청구 대상 서른 명을
한 화면에 모으는 것은 그냥 목록이다. 대시보드가 그 일을 한다.

**질문은 버튼 하나가 여러 건을 발사하는가**이고, 둘을 순서대로 묻는다.

```
① 항목마다 사람이 정할 값이 같은가
     같거나 없다 → 묶어도 된다
     항목마다 다르다 → 개별. 묶으면 그만큼의 판단이 사라진다

② 되돌리는 일이 또 밖으로 나가는가
     나간다 → 묶지 않는다
```

**②는 시간으로 재지 않는다.** 영상 회수는 일주일 뒤에도 표시 하나를 남기는 일이지만,
청구 취소는 **학부모에게 문자를 한 통 더 보낸다** — 결제선생이 취소를 안 알려 주기
때문이다(2-5). 그래서 잘못 나간 청구 서른 건의 값은 문자 서른 통이 아니라 예순 통이다.
**돈은 문자를 두 번 낳는다.**

| | 보기 | 쓰기 | 왜 |
|---|---|---|---|
| **출결 확정** | 반 · 주차 | **묶음** | 값은 이미 OMR 이 들고 있다. 손댈 것만 손대고 확정은 한 번 |
| **OMR 판독** | 반 · 주차 | **묶음** + 개별 보정 | 기계가 읽을 수 있는 것은 묶고, 못 가르는 장만 사람에게 |
| **영상 지급** | 지급 내역 | **묶음** 지급 + **개별 회수** | 누가 받을지는 출결이 정한다. 손으로 하는 것은 회수뿐이고, 수동 지급은 만들지 않는다 |
| **교재 배부** | 반 | **묶음** + 개별 | "이 반 전원이 샀다" 는 사실이지 판단이 아니다 |
| **계정 발급** | 전체 | **묶음** | 정할 값은 "어느 반" 하나고 나머지는 엑셀이 들고 있다 |
| **교재 청구** | 반 · 전체 | **개별** | 학생마다 낼 것이 다르고(1-6), 잘못 나가면 되돌리기가 또 나간다 |
| **클리닉 배정** | 전체 | **개별** | 건마다 자리와 시간이 다르다. 열 건을 맞춘 사람은 이미 열 번 배정한 것이다 |
| **전화** | 전체 | **개별** | 통화 내용이 집마다 다르다. 애초에 묶을 수 있는 일이 아니다 |
| **주차 날짜** | 반 | **전파** | 정하는 값은 하나인데 뒤가 따라 밀린다(1-3). 묶음도 개별도 아니다 |

**묶음을 만들 때는 확인 화면을 붙이지 말고, 근거가 없는 행을 묶음이 스스로 뱉게 한다.**
`확인필요`(2-3) · `미입력`(3-4) · 매핑 보류(3-3)가 전부 그 모양이다. 행마다 O/X 를
받는 화면은 묶음이 아니라 개별을 세로로 쌓은 것이고, 스무 번째 행에서는 아무도 안 본다.

---

## 부록 — 지금 시스템과의 차이

여기부터는 개발용이다. 위 흐름을 지금 시스템이 얼마나 담을 수 있는지 실사한 것이고
(2026-08-12 첫 실사 · 2026-08-19 갱신), 흐름 자체를 이해하는 데는 필요하지 않다.

### 옮긴 것

2026-08-18~19 에 여덟 갈래로 나눠 들어갔다.

| | 어떻게 됐나 |
|---|---|
| **반** | `curriculum.Class` 엔티티. `CourseEnrollment.klass` · `ClassSession.klass` 로 붙는다. 문자열 사본 둘(`Student.current_class` · `CourseEnrollment.class_name`)은 지웠다 |
| **주차 내용** | `CourseWeek` 가 커리에 매달린다 |
| **회차** | `ClassSession` 이 반을 안다. `UQ(반, 주차)` |
| **구분·과목** | `curriculum.Subject`(`track` + `name`). 구분은 잠기고 과목은 새로 만들 수 있다 |
| **총주차** | `Course.total_weeks` |
| **반 만들기** | `POST /api/admin/classes` — 커리+반을 한 번에 만들고 회차가 총주차만큼 자동으로 생긴다 |
| **계정 → 명단** | 계정 발급이 `CourseEnrollment` 를 만든다. 조교가 반을 골라서 넣는다 |
| **출결 기본값** | `미입력` 이 생겼다. `결석` 은 조교가 찍은 것이다 |
| **동보 승인** | 걷어냈다. 신청 + 결석 확인이 차면 바로 나간다 |
| **영상 중복 지급** | 학생×영상으로 막는다. 만료가 안 밀린다 |
| **전화번호** | 정규화한다. 계정 판정이 세 갈래로 갈리고 애매한 행은 세워 둔다 |
| **OMR → 출결** | 대조되면 출석이 찍힌다. 사람이 찍은 값은 안 덮는다 |
| **교재** | `Product` 가 커리에 붙는다. `세트`·`낱개` 표시 · 남의 커리 교재는 목록에서 빠진다 |
| **현보 두 반 기록** | 방문한 반에 `출석`, 원래 반에 `결석(현보)` 를 한 번에 찍는다 |
| **클리닉 대상** | 채점이 끝나면 생긴다 — 출석 + 응시 + 평균 미달 |
| **출결 확정 통지** | 첫 확정에만 반 전체에 큐로 쌓인다(템플릿 대기) |
| **주차 일정** | 반에서 고친다. 앞을 고치면 뒤가 같은 폭으로 밀리고 번호는 안 움직인다. 주차 추가·삭제도 반에서만 하며 커리 총주차는 안 바뀐다 |
| **소비자 화면의 날짜** | `ClassSession.session_date` 를 본다. `CourseWeek` 는 날짜를 안 담는다 — 반이 둘이어도 각자 자기 일정을 본다 |
| **반 이동** | 수강의 반을 갈아 끼운다. 지난 기록은 옛 반에 남고, 기록이 있는 회차는 명단에서 그 학생을 안 뺀다 |

### 아직 남은 것

| | 지금 | 필요한 것 |
|---|---|---|
| **날짜가 하는 일** | `release_at` 이 날짜로 공개를 발동한다 | **아무것도 발동시키지 않는다** — 부여·회수는 입력 시점 기준(1-4) |
| **클리닉 슬롯** | 정원이 `1` 로 못 박혀 있다 — 기본값 · `editable=False` · `CheckConstraint` 셋 | **조교 수**가 정원이다. 커리가 시간대를 갖고, 고친 날 이후부터 적용(3-7) |
| **교재 표지** | 사진 자리가 없다 | 표지 사진(1-6). 커리에 붙는 것과 세트/낱개는 됐다 |
| **반이 둘인 학생** | 학생·학부모 화면이 첫 수강 하나만 본다 | 달력은 합치고, 주차·성적은 반을 골라 본다(4-1) |

- **노쇼 누적·클리닉 정지**는 이미 자리가 있다(3-7)
- **선지 번호와 추가 마킹란**도 이미 저장할 자리가 있다(4-3)
- `week_no`·`CourseWeek` 를 참조하는 파일이 **46개**다(2026-08-19 실측). 영상 권한·게시판·
  출결·홈 화면이 전부 걸린다
- **지금이 제일 싼 시점이다** — 운영 데이터가 데모뿐이고 아직 오픈 전이다.
  오픈 후에는 실제 출결·영상 권한을 이관해야 한다

왜 만드는가

최종 목적지 · 성공 지표

흩어진 업무(성적·영상·클리닉·결제·게시판/문의·알림)를 하나의 LMS로 통합 — 학생에겐 단일 진입점, 관리자에겐 단일 운영 콘솔. 완성도의 척도는 기능 수가 아니라 아래 지표의 개선폭입니다.

항목 As-is (현재) To-be (LMS 도입 후) 측정 지표
성적 처리·배부 OMR 수합 → 아카플로우 채점 → 카톡 발송 → 성적표 인쇄·배부 (수작업 다단계) 스캔본 자동채점+보정 → 누적성적표·알림 자동 → 앱 조회 처리~배부 소요시간 · 수작업 단계 수
영상 권한 부여/회수 카톡 개별 접수 → 유튜브 수동 공개 → 엑셀 기록 → 1주 후 수동 비공개 (전과정 수동) LMS 신청~승인~안내~만료 자동 관리(권한작업은 할일·알림 보조) 건당 처리시간 · 수동 처리 건수 / 자동화율
교재 청구·결제 등록생마다 카톡 청구서 개별 발송 → 결제 확인 학생 버튼 클릭 → 자동 청구 → 대시보드에서 확인 청구 방식(수작업→자동) · 확인 소요시간
클리닉 신청·배정 카톡 채널 접수 → 수동 승인·미트링크 동봉 LMS 신청·배정·시간제한 링크 자동 노출 접수·배정 일원화 · 수작업 여부
문의·상담 카카오톡 상담 LMS 자체 채팅/게시판 문의 채널 일원화
학생 정보 접근 아카플로우·유튜브·결제선생·카톡 분산 LMS 단일 로그인 진입점 이용 외부 채널 수 · 단일사이트 이용률

※ 각 지표의 구체 목표치(%·시간)는 실측 baseline 확보 후 관문 5(성공지표 목표치 확정)에서 결정.

어떻게

추진 원칙 & 선결 검증

리스크를 먼저 검증(PoC) → 의사결정 관문을 순차 통과 → 구축·현행 이관

PoC선결 — 기술 검증을 가장 먼저

불확실성이 큰 3가지를 먼저 검증해 예산(관문 1)·기술노선(관문 4) 판단 근거로 투입합니다.

  • OMR 자체인식 정확도 검증 (6-1)
  • YouTube 권한 자동화 방식 검증 (6-7)
  • 클리닉 녹음 방식 검증 (8-5)

상부 결정 사항

의사결정 관문 5

관문 1사업 범위·예산·일정 승인

문제점 — OMR 자체인식은 개발비 증가 + 정확도 미검증(미달 시 수동보정 인건 지속). ‘1차 개발 범위·예산·일정’ 승인과 함께 채점 노선을 결정해야 함.

A. 자체 인식 개발 (현 결정)

완전 통합 · 외부 구독 제거 · 장기 운영비 ↓

초기 개발비 ↑ · PoC 필수 · 정확도 리스크

B. 외부 채점(아카플로우 등) 결과 업로드 유지

개발비 ↓ · 검증된 정확도

외부 구독료 지속 · 통합 미흡 · 수작업 잔존

C. 상용 OMR 엔진 연동

검증된 정확도 · 개발 단축

라이선스 비용 · 커스터마이즈 제약

결정해야 할 사항 — 노선 택일 + PoC 예산·중단 기준. (A=초기 개발비 큼·운영비 작음 / B=초기 작음·구독료 지속 → PoC로 A 타당성 먼저)

관문 2개인정보·법무 검토 (8-1)

  • 클리닉 감독 녹음본 동의·노무 이슈 (민감 — 방식·보관은 관문 4-B에서 함께 결정)
  • 전화번호 기반 원번·학부모 연락처·성적 등 민감정보 처리방침
  • 통합 개인정보 처리방침·동의 절차 채택

결정해야 할 사항 — 개인정보 처리방침·동의 절차 승인 (착수 전 리스크 차단)

관문 3외부 연동·계약

  • 결제선생 임베드 + 향후 PG 전환 옵션 (6-5)
  • 카카오 알림톡 계약 (6-8) / 신규생 계정 발송 채널 (8-3)
  • Google Workspace·Meet 요금제 — 녹음·API 요건·비용 (6-3)
  • YouTube 50계정 한도 (8-2) — 아래 관문 4-A와 연동

결정해야 할 사항 — 외부 서비스 계약·요금제 승인

관문 4-A영상 권한 자동화·호스팅 노선 (6-7 · 8-2)

문제점 — RPA 봇은 ① 약관 정면 위반 ② 구글이 자동화 로그인을 기술 차단 → 상시 고장 ③ 적발 시 계정 정지 = 사업 중단(연쇄) ④ UI 취약 + 50계정 한도로 확장 불가 ⑤ 애초에 공식 API 없음. (봇 운영엔 별도 PC·인건이 숨은 비용)

A. YouTube 유지 + 봇 자동화

호스팅 자체는 무료

약관위반·계정정지 리스크 · UI 유지보수 · 50명 초과 불가

B. YouTube 유지 + 영상 사본 분할(50명 단위)

당장 새 인프라 불필요

사본마다 권한관리 폭증 · 근본 해결 아님

C. 전용/자체 영상서버 전환 (DRM·서명URL)

자체 권한관리 · 약관/50한도에서 해방 · 안정

월 스트리밍·트래픽 비용(사용량 비례) + 개발 필요

결정해야 할 사항 — 노선 택일. 봇은 PoC 검증에 한정, 전환 트리거·예산 사전 승인 (중장기 C 전환이 리스크·비용 모두 유리)

관문 4-B클리닉 녹음 방식 + 녹음본 개인정보·보관 (8-5 · 6-3)

문제점 — 미트 자체 녹화는 ① 유료 요금제(Business Standard+) 필요 ② 항상 영상+음성 → 음성전용 불가·저장/프라이버시 부담 ↑. 감독용은 음성만, 그리고 조교가 끄거나 깜빡할 수 없는 자동 녹음이어야 함.

A. 상용 봇 API (Recall.ai 등, ~$0.5/녹음시간)

도입 빠름 · 초기비용 낮음 · 월정액 0 · 음성전용 · 중앙 자동

사용량 비례 과금 · 데이터 국외이전(위탁·동의 필요)

B. 봇 self-host (Vexa·Attendee 등 오픈소스)

음성전용 · 중앙 자동(조교 못 끔) · 데이터 사내 보관 → 국외이전/위탁 이슈 해소 · SW 무료

서버·인프라 직접 구축·운영 부담 · 봇 참가자 표시·구글 봇차단 대응 · 유지보수 · 초기 기술 역량 필요

C. 미트 자체녹화 (Business Standard+ ~$14/계정·월)

단순 · 컴플라이언트(사내 Drive)

계정당 월 요금 + 영상 저장 강제

개인정보·녹음본 보관 — 학생·학부모 사전 고지·동의(미성년자 법정대리인) / 제3자 봇 사용 시 위탁계약·국외이전 동의 / 보관기간·파기 정책 + 녹음본 저장 스토리지 비용(보관기간과 직결). → self-host·사내 보관이 개인정보·국외이전 리스크 최소화.

결정해야 할 사항 — 녹음 방식 택일(실제 물량 기준 A=변동비 vs B=고정비 손익분기 계산) + 개인정보 동의·(제3자 시)위탁 절차 + 보관기간 정책

관문 5런칭·현행 이관·성공지표 확정

  • 등록/미등록 운영·계정 자동발급 (6-9, 3.1.5)
  • 성공지표 목표치 확정 (5장)
  • As-is(카카오톡·엑셀) → LMS 데이터 이관·병행운영·전환 시점

결정해야 할 사항 — 실서비스 전환·이관 시점 및 성공지표 목표치 승인

2026-07-28 확정. 이전 시도(스크롤 스크러빙 영상 시퀀스)는 폐기했다. 지금은 **훨씬 단순하다.**

## 0. 한 줄 요약

**검은 화면. 헤드라인 두 줄. 오른쪽에 한종철. 배경 어둠 속에 통합과학 6개 대단원이 숨어 있고, 건드리면 드러난다.**

## 2. 네비게이션 바

- 배경: **순검정** (히어로와 이어져 경계가 없다)
- 왼쪽: 로고 — `한종철 통합과학` + 섹션 링크 `커리큘럼` `정오표` `문의하기`
- 오른쪽: **[ 로그인 ]** 버튼 하나

**로그인 전에는 "LMS"를 걸지 않는다**(2026-07-28 사용자 지시). 비로그인 방문자에게
LMS 는 제품 내부 명칭이고, 이 화면이 파는 것은 강의다.

nav 에도 **같은 먼지가 뜬다.** nav 는 항상 불투명 검정이라 그 아래 히어로 먼지밭을
가로로 잘라 먹는다 — 이어 주지 않으면 화면 맨 위 64px 만 텅 빈 띠로 남아 "덮개"라는
전제가 깨진다. 밀도는 개수가 아니라 **면적당으로** 맞춘다(실측 nav 6.46 vs 히어로 6.11
per 천px²). **커서에 반응하지 않고 애니메이션도 하지 않는다** — 연속성만이 목적이고,
화면 맨 위에서 계속 움직이는 것은 그 자체가 방해다.

섹션 링크는 아래 세 섹션으로 그냥 내려보내는 앵커다. 390px 에서는 로그인 버튼을
20px 침범하므로 접는다 — 스크롤하면 순서대로 나오므로 이동 수단이 사라지지 않는다.

## 3. 헤드라인 — 확정

```
통합과학도
철두철미하게
```

**확정**(2026-07-28). 텍스트 2줄, 왼쪽 배치. 이미지 아님.

지어낸 카피가 아니라 **한종철이 메가스터디에서 이미 쓰는 슬로건 원문**이다
("생명과학도 철두철미하게!" / "통합과학도 철두철미하게!"). 그래서:

- **검증이 끝나 있다** — 본인 브랜드로 이미 굴러가는 말
- **이름의 '철'과 교재 브랜드**(철두철미 개념완성/실전모의고사/완자)가 한 줄로 꿰인다
- 조사한 과학강사 38명의 지배적 수법(이름을 문장에 녹이기 — 장풍 "정상을 향한 바람",
  백호 "Yes 백호!")과 같은 계열이면서, **그중 유일하게 태도가 아니라 방식을 말한다**
- 조사 근거상 "관리"라는 명사는 학부모에게 동네학원 언어로 읽혀 지뢰인데,
  "철두철미"는 같은 뜻을 사자성어로 우회한다
- **'도'** 한 글자가 생명과학 이력을 보증으로 바꾼다 — 전환기 랜딩의 핵심 부담을 조사가 해결

> 후보 10개를 뽑아 비교한 기록: `local/landing-refs/03-헤드라인-후보.md`
> (본인 목소리·라이벌·전환기·학부모·카피기술 5개 관점 × 6개 = 30개 → 10개)
> 결과적으로 **지어낸 것보다 이미 쓰던 말이 이겼다.**

### 서체 — SUIT Variable **확정**(2026-07-28)
`cdn.jsdelivr.net/gh/sun-typeface/SUIT@2` 가변 1파일로 100~900을 쓰고 헤드라인은 900.
**본체 앱(`frontend/index.html`)과 같은 서체다** — 랜딩과 로그인 후 화면이 다른 글씨로
보이면 같은 서비스로 안 읽힌다. 교체를 검토했으나 그대로 가기로 했다.

### 조판 메모
- 줄바꿈은 `통합과학도` / `철두철미하게`. 2행이 1행보다 길어 왼쪽 정렬에서 계단이 진다
- **부제·설명을 붙이지 않는다.** 이 2줄과 사진이 히어로의 전부다
- 두 줄 사이는 `line-height` 가 아니라 **flex `gap`(`--h1-gap`, 기본 .14em)** 이
  벌린다. line-height 는 글자 위아래 여백을 같이 키워서 "두 줄 사이"만 따로 조절할
  수가 없다. em 이라 글자 크기를 바꿔도 비율이 유지되고, 디버그 패널의 노브가 이 변수를
  직접 만진다

## 4. 배경 — 먼지밭

검정 위에 아주 작은 먼지 4000개가 떠 있다. 커서가 지나가면 그 자리의 먼지가 밖으로
밀려나며 옅어지고, 커서가 떠나면 서서히 되메워진다. 그게 전부다.

| | |
|---|---|
| 개수 | 4000 (1440×900 기준 100px² 당 2.9개) |
| 크기 | 1.0 ~ 4.0px |
| 밝기 | 0.10 ~ 0.40, 반짝임 폭 0.40 |
| 부유 | 바람이 없어도 10px 반경으로 아주 느리게 |
| 색 | `--glow` (로열 H224) · `mix-blend-mode: screen` |

값은 전부 사용자가 디버그 패널로 맞춰 확정한 것이다(2026-07-28).

### 바람
커서 둘레의 창 함수 `w = exp(-d²/2R²)` 로 먼지를 민다. R = min(W,H) × 0.10.

- **밀어냄** 커서 반대 방향으로 0.85R. 정중앙은 방향이 정의되지 않으므로 입자마다
  고정 탈출 방향을 줘서 구멍 한가운데 점이 박히는 것을 막는다
- **쓸림** 커서 속도를 0.16 만큼 물고 간다 — 진행 방향으로 흐른다
- **소용돌이** 접선 성분 0.22. 없으면 구멍이 정확한 원이 된다
- **옅어짐** 밝은 자리에서 0.85 만큼 옅어진다. 이게 없으면 밀린 먼지가 경계에 쌓여
  링이 보인다
- **비대칭 감쇠** 밀릴 때 k=9.0, 되메워질 때 k=1.6. **이 비대칭이 "걷힌다"를 만든다**

### nav 에도 먼지를 잇는다
nav 는 항상 불투명 검정이라 그 아래 먼지밭을 가로로 잘라 먹는다. 이어 주지 않으면
화면 맨 위 64px 만 텅 빈 띠로 남는다. 밀도는 개수가 아니라 **면적당으로** 맞춘다
(실측 nav 6.46 vs 히어로 6.11 per 천px²). 커서에 반응하지 않고 애니메이션도 하지
않는다 — 연속성만이 목적이고, 화면 맨 위에서 계속 움직이는 것은 그 자체가 방해다.

### 포인터 판정은 이벤트로만 한다
마운트 시점 `matchMedia('(hover:hover) and (pointer:fine)')` 를 믿으면 안 된다 —
터치 노트북과 헤드리스에서 참이라, 영영 오지 않을 `pointermove` 를 기다리며 히어로가
검게 남는다. 기본값은 "포인터 없음"(자율 배회가 대신 분다)이고, `pointerType` 이
touch 가 아닌 `pointermove` 가 실제로 한 번 들어온 뒤에야 바람이 커서 소유로 넘어간다.

### 배우고 간 것 넷

**① 톤 위계가 "촌스러움"의 정체였다.** 에셋의 원래 밝기가 제각각(중간휘도 134~215)
이라 같은 opacity 를 주면 어떤 것은 헤드라인보다 밝아진다. 마스크 모양이 아니라
**위계**의 문제였다. 에셋별 `brightness()` 계수로 피크 렌더휘도를 전부 ≈68 에 맞추고
헤드라인 1행을 110 으로 두자 해결됐다. — 이 교훈은 지금 배경에도 그대로 적용된다.

**② 반응 단위는 개체가 아니라 픽셀이어야 했다.** `opacity` 는 요소 전체에 걸리므로
"원자의 왼쪽 고리만 보인다"를 표현할 방법이 없다. DOM 10개를 캔버스 2장(오프스크린에
구운 잉크 + 화면에서 오려내는 마스크)으로 바꿔야 "조금씩 보인다"가 됐다.

**③ 패커에 계산 버그가 있었다.** `rotate(expand=True)` 는 캔버스를 최대 1.41배 늘리는데
그걸 회전 **전** 크기의 격자로 줄여, 모든 발자국을 그 배수만큼 작게 잡고 있었다.
화면에서는 회전 후 크기로 자리를 차지하므로 패커만 "안 겹친다"고 믿었다. 여백을
30px 까지 키워도 겹치던 원인이 이것이다. 브라우저에서 잉크 픽셀로 재서 잡았다.

**④ 낡은 제약을 계속 지고 있었다.** 여백 22~30px 의 근거는 "런타임에 이웃이 서로
±12px 다가온다" 였는데, 모티프를 한 번 구워 통째로 그리게 된 뒤로는 상대 이동이 0
이었다. 8px 로 줄이자 크기와 유기성이 동시에 늘었다(12 → 14.3vw, CV 0.05 → 0.18).

### 유기적 배치를 수로 정의했던 것
존 격자에서 칸마다 하나씩 뽑으면 줄이 보인다. 그래서 자유 배치로 1400판을 뽑아
점수가 가장 높은 것을 골랐다. `pack-layout.py` 에 남아 있다.

```
점수 = 2.6·(최근접이웃 거리의 변동계수) − 0.22·(x 나 y 가 5.5% 안에 든 쌍) + 1.5·(퍼짐)
```

여백이 뭉침을 봉쇄한다는 것(30px 이면 모든 쌍이 최소 60px 떨어져 CV 0.08)과,
꽉 채우면 고를 것이 없다는 것(최대 크기에서 유효 후보 9판)이 여기서 나왔다.

## 6. 채널톡 — 상시 부유

**채널톡 위젯이 페이지 전체에 계속 떠다닌다.**

- 그래서 **히어로에 별도 상담 CTA를 두지 않는다.** PRD §3.3.3의 1차 목적(상담·문의 전환)은 채널톡이 담당한다
- 윤도영도 채널톡을 쓴다 — 서포트봇뿐 아니라 교습비 반환기준·수강료 게시표까지 채널톡 문서로 호스팅
- 검토 자료: `local/sources/research/2026-07-17-채널톡-도입검토.md`, `2026-07-18-채널톡-전체기능.md`

### 6-1. 키 주입 — 정적 · 동기 (2026-08-04 확정)

`index.html` 헤드의 **클래식 스크립트 한 줄**이 `window.__CHANNEL_TALK_KEY__` 를 세우고,
`chat.js` 가 모듈 로드 시점에 그걸 읽는다. 지금은 빈 문자열이라 위젯이 뜨지 않는다.

- **빌드타임이 아니다.** 랜딩은 Vite 밖의 무빌드 정적 페이지다. 빌드타임 주입을 택하면
  이 페이지에 번들러를 새로 들이는 일이 되고, 배포 경로가 미정인 지금 아무 정적
  호스팅에나 그대로 얹히는 성질을 잃는다
- **클래식 스크립트인 것이 계약이다.** `chat.js` 는 모듈이라 defer 로 늦게 돌고,
  헤드의 클래식 스크립트는 파싱 중 즉시 실행돼 **항상 먼저 선다.**
  비동기(`fetch('/config.json')`·서버 후주입)로 바꾸면 키를 놓친다
- **키는 시크릿이 아니라 커밋한다.** 채널톡 부트 스니펫이 페이지 소스에 그대로 노출하는
  공개 값이다. 채널톡이 실제로 시크릿으로 다루는 건 서버 쪽 `memberHash`(HMAC-SHA256)고
  랜딩에는 쓸 일이 없다
- 발급: 웹 데스크 좌측 하단 → **채널 설정 > 일반 설정 > 버튼 설치 및 설정 > 채널톡 버튼 설치**.
  설치 화면이 주는 `<script>` 스니펫은 **붙여넣지 말 것** — 부트는 `chat.js` 가 한다.
  두 번 넣으면 두 번 부팅된다

### 6-2. 런처가 앉는 자리 (2026-08-04 실측)

채널톡 번들(`ch-plugin-core`)에서 읽은 기하다 — 문서에 공개된 값이 아니라 실물에서 뽑았다.

| | 값 |
|---|---|
| DOM | `<div id="ch-plugin">` 을 `body` 끝에 붙인다 |
| 위치 | `position:fixed` · `right:24px` · `bottom:calc(env(safe-area-inset-bottom) + 24px)` |
| 크기 | 56px |

`viewport-fit=cover` 를 쓰므로 아이폰 세로에서는 세이프에어리어(약 34px)만큼 더 올라온다.

**푸터 사업자 정보와 겹쳤다** — 390px 22×22 · 430px 8×22 로 `주소` 를 덮었고,
세이프에어리어를 더해도 남았다. 600px 이상과 데스크톱(여유 224px)은 처음부터 안전.
그래서 모바일 블록에서 푸터 아래에 런처 자리를 비운다:
`padding-bottom:calc(env(safe-area-inset-bottom) + 24px + 56px + 16px)` → 여유 16px 로 고정
(세이프에어리어 0·21·34 모두 동일 — 런처와 같은 `env()` 를 쓰므로 함께 움직인다).

### 6-3. 키를 받은 뒤 검증 절차

1. `index.html` 의 `window.__CHANNEL_TALK_KEY__` 에 키를 넣는다. **따옴표 안에 키만** —
   앞뒤 공백·줄바꿈은 `chat.js` 가 떼지만(`chat.test.js` 가 못 박는다) 넣지 않는 게 맞다
2. `cd frontend && npm test` — 39건 전부 통과해야 한다
3. `cd frontend/landing && python3 -m http.server 8899` 로 띄우고 브라우저로 연다
4. **콘솔에 에러·경고 0.** 위젯이 오른쪽 아래에 뜬다
5. `채팅으로 문의하기`·`제보하기` 를 각각 누른다 — 메신저가 열리고,
   `setPage` 로 `상담 문의`·`정오표 제보` 가 실려 상담 맥락이 채널톡 쪽에 남는지 확인
6. **390px 로 줄여 페이지 최하단까지 스크롤** — 런처가 사업자 정보를 덮지 않는지.
   덮으면 6-2 의 패딩 산식이 깨진 것이다(채널톡이 런처 크기를 바꿨을 수 있다 — 다시 실측)

### 7-1. 커리큘럼

**이 섹션의 임무는 판매가 아니다.** "생명과학 1타가 통합과학을 하나"라는 의심에 대한
답이다. 통합과학은 물·화·생·지 전 영역이라 그게 첫 질문이 된다. 그래서 강좌 목록이
아니라 **6대단원 전 영역 커버리지 증명**이고, 히어로("어둠 속에 전부 있다")와 같은
주장을 두 번째로 하는 구조다.

#### 축 — 시기축을 쓰지 않는다
2028 첫 사이클이라 월별 배치를 확정할 수 없고 갱신 부담이 크다. 조사에서 진도표를
메뉴로 만들어 놓고 못 채운 곳이 둘이었다(김현정 "내용 준비중", 준과학 404).
또 **LMS의 주차 커리큘럼과 분리해야 한다** — `backend/apps/curriculum/`의
`released()`는 PRD §4에 따라 "시작된 주차까지만" 공개하고 목적이 경쟁사 차단이다.
비로그인 랜딩에 주차 진도를 그리면 그 원칙을 정면으로 깬다.

→ **갱신 부담이 0인 고정축 2개만**: 6대단원(교육과정이 정함) × 4단계(업계 표준어).

> **강좌 라인업은 새로 만들지 않는다**(2026-07-28 확정). 지금 있는 것 —
> 철두철미 시리즈(개념완성/실전모의고사/완자), 로직N제, 자분기, 만점시퀀스, M.D.G.C —
> 을 아래 4단계 × 2트랙 축에 **재배치**한다. "철두철미"는 사용 가능하다(A-2 해소).

#### 구성
```
커리큘럼                                        최종 갱신 26.07.28
2028 수능, 과학은 통합과학 하나다.        ← 리드 (카피 확정 필요)

  [ 고1·고2 내신 통합과학 ]  [ 2028 수능 통합과학 ]   ← 목적 2트랙

  입문 → 개념완성 → 문제풀이 → 직전대비              ← 4단계 (세로 계단)
  ┌────────────────────────────────┐
  │ 개념완성                 [필수] │  단계 라벨 + 배지
  │ 철두철미 완자 통합과학          │  강좌·교재명
  │ 물화생지 전 영역 개념의 완결     │  한 줄, 명사 종결
  │ ● 물질과 규칙성 ● 시스템과 상호작용│  대단원 칩 ← 우리만의 축
  └────────────────────────────────┘

  ─ 실전 모의고사 ─                                ← 단계 축 밖 별도 밴드

  6대단원 × 4단계 커버리지 매트릭스                  ← 6행이 다 차는 그림 = 증명
```

**따르는 것** (어휘·정보 구조는 인지 비용이라 표준을 쓴다)
- 이름은 `커리큘럼`. 로드맵·진도표·학습플랜 안 씀
- 단계 어휘는 업계 표준어. 새 조어 만들지 않음
- 카드는 **4요소로 절제**: 단계 라벨 + 강좌/교재명 + 한 줄 + 배지
- **가격·강의수·수강기간 안 넣는다** — 커리큘럼 층의 업계 불문율(예외 0건)
- 실전 모의고사는 단계 축 밖 별도 밴드 (메가 강사 4명 전원의 처리)

**깨는 것**
- **이미지·영상 커리큘럼을 만들지 않는다.** DOM 텍스트 단일 소스 하나만 →
  표/포스터 불일치와 방치를 구조적으로 차단
- **모달·팝업이 아니라 스크롤 섹션** (조사 대상 전무)
- **커리큘럼에도 `최종 갱신` 날짜를 박는다** — 정오표에서만 쓰이던 관리 신호를
  확장하면 두 섹션이 하나의 주장으로 묶인다 (업계 전무)
- **6대단원 축 도입** — 업계는 단계×과목 2축뿐, 교육과정 단원을 올린 곳이 없다

**전환기 신호**: 통합과학은 2028이 첫 시행이라 **수능 기출이 없다.** 그래서 업계 표준
6단계 중 `기출분석`을 뺀다. 이걸 화면에서 한 줄로 말하는 것 자체가 전문성 신호다.
(다만 "기출이 없다"가 불안을 자극할 수 있어 톤 판단 필요)

**하단 고지** (EBS 어법을 빌린다):
> 본 커리큘럼은 2028학년도 대비 기준이며, 교육과정·출제 방향 확정에 따라 일부 변경될 수 있습니다.

### 7-2. 교재 정오표

**첫 통합과학 교재부터 정오표를 세워두는 것 자체가 포지션이다.**
대성마이맥 통합과학 강사 5명 중 정오표 운영자는 1명뿐이고, 시대인재북스는 과탐 교재에
"정오표 확인 방법.pdf"를 정오표라고 내려준다.

#### 구성
```
교재 정오표
교재에서 확인된 오류는 전부 여기 올립니다.
최근 갱신 26.07.28 · 교재 4종 · 정정 12건        ← 3초에 "살아있음" 판정

교재명                          대상      정정   최초 게시   최종 수정
철두철미 완자 통합과학2 [NEW]   고1 내신   5건   26.03.11   26.07.28
철두철미 완자 통합과학1         고1 내신   4건   26.03.11   26.06.24
        ↓ 행 클릭 → 인라인 확장 (★업계 유일)
위치       페이지  수정 전        수정 후       반영
3단원 2강   142    …감소한다     …증가한다    26.07.28
                                       [엑셀 내려받기]

여기 없는 오류를 발견하셨나요?                    [ 제보하기 ]
```

**따르는 것**
- 이름은 **`교재 정오표`** (전수 14/14 표준). 윤도영식 `정오사항`은 개인 표기라 안 따름
- 항목명은 `{교재명} 정오표` — 교재명이 앞
- **제보 채널을 반드시 붙인다** — 정오표는 업계에서 혼자 서지 않는다
- 화면 날짜 `YY.MM.DD`, 표 스키마는 업계가 파일 안에서 합의한 5열 그대로

**깨는 것**
- **파일이 아니라 웹 표가 기본.** 다운로드는 보조 버튼
- **`최종 수정일`을 1급 데이터로 두고 정렬 기준으로** — 업계는 제목에 수기로 박는다
- **로그인 벽 없음** (메가·이투스는 로그인 필수 → "관리한다"는 메시지를 스스로 깎는다)
- **스크린샷 금지** — 윤도영은 5개 중 4개가 PNG라 검색·복붙·접근성이 0
- **"더보기로 N개만" 금지** — 윤도영은 이 컷 때문에 최근 갱신 2건이 정확히 숨었다

#### 운영 부담 설계 ★
업계 실패는 전부 여기서 나왔다 — 제목에 날짜 수기 입력 → 박제(윤도영 파일 안에
`최근 반영일: 2023.04.18`과 실제 `2026.06.24`가 나란히 보인다), 파일명 규칙 혼재
(지학사는 한 사이트에 5가지 포맷), 정렬 붕괴. **사람이 하는 일을 줄이는 게 설계 목표다.**

- **운영 주체 확정**(2026-07-28): **우리가 직접 올린다.** 강사·조교에게 넘기지 않는다.
  → 업계 실패 사례(담당자 부재로 섹션이 죽는 것)의 주원인이 제거됐다.
  다만 입력이 편해야 지속되므로 아래 붙여넣기 입력 설계는 그대로 간다
- **입력 창구는 하나. 새 CMS를 만들지 않는다.** LMS에 이미 있다 —
  `backend/apps/boards/models.py`의 `Post.Category.ERRATA`(코드 확인 완료).
  랜딩은 이 데이터를 공개 API로 읽어 렌더한다
- **다만 현재 `Post`는 `title`/`body`뿐이라 웹 표를 못 그린다**(확인 완료).
  `errata_items` 자식 테이블 신설 + **"엑셀에서 복사 → 붙여넣기 → 행 파싱"** 입력 권장.
  xlsx 다운로드는 저장된 행으로 **서버가 생성** → 사람이 파일명을 안 짠다
- **날짜는 사람이 입력하지 않는다.** `created_at`/`updated_at` 자동 기록을 2열로 그대로.
  ⚠️ 현재 `Post.updated_at`은 `auto_now` 없는 nullable(확인 완료)이라,
  정오 항목만 고치고 부모 글 `updated_at`을 안 올리면 **정렬이 그대로 무너진다**
- **빈 기간을 미리 설계한다.** 정오표는 교재 출시 직후에 몰리고 그 뒤 산발적이다.
  빈 섹션을 숨기지 말고 빈 상태로 보여준다 — 숨기면 "없는 것"과 "안 하는 것"이 구분되지 않는다
- 수식·도표 정정은 이미지가 불가피하니 허용하되 **텍스트 설명 + 대체텍스트 필수**로 강제
